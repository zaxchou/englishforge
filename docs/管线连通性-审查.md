# 管线连通性审查（2026-09-28）

用户的问题：「**既然已经有了账户系统之后，生成的题库都应该是定制的、可对照的，对吧？而且应该是保存在账户里的。**」
以及：「**把整套流程再串联一遍，对照一下之前做的所有管线，看看是不是都连通、都相关联，比如题库这一块。**」

这份文档就是逐段核对的结果。**结论先说**：语料 → 出题 → 富化 → 审核这条**离线**管线是通的，但它与
"练习系统"之间**断在最后一步** —— 512 道生成题里只有 20 道被手工抄进代码，其余 492 道一直躺在 `out/` 里
没进过 app。本轮把这一步接通（题进账户题库），并修掉 3 个连带缺陷。

## 二、本轮修掉的（都有实测）

**G1 · 断点本身：生成的题进不了 app。**
`make-pilot.py` 是"一次性手抄 20 道"的脚本，不是通道。新增 `scripts/push-items.py`：
把 `out/` 里富化过的题按前端 `Question` 契约转换后**导进账户题库**（`items` 表）。
- 幂等：`itemId = <skill>:<语料id>`，重复导入只更新，所以管线可以反复生成、反复替换。
- 去重：跳过 `sourceRef` 已在仓库题目里的（避免同一句语料进两次）。
- 实测导入用户账户：**97 道**（s2 36 / s3 22 / s4 39），跳过 55 道（缺字段或出处已在仓库）。
- 实测接入抽题池：主宾格 `做过 0/53 题` → **`0/57 题`**（+4 道账户题）。

**G2 · 题库与"进度"混在一起清。**
`resetAccount` 原本把 `content_reviews` 也一起删了 —— 而审核结论决定"这题算不算能力证据"，
属于**内容**不属于进度。已把 `content_reviews` 与 `items` 从"清空进度"中摘出：**清空进度不动题库与审核结论**（有测试）。

**G3 · 审核结论只躺在本机。**
账户题库里的题，审核页给结论时会**同时写回数据库那一行**（`items.review_status`），换浏览器也不丢；
仓库自带的老题没有库行，继续走本地标记。只推变化的那几条，避免一次点击发几百个请求。实测：勾"通过" → 库里该行变 `reviewed`。

**G4 · 列表接口静默只返回 1 行（既存缺陷）。**
`num(null, 200)` 曾返回 `0`（因为 `Number(null) === 0` 是有限数），被 `Math.max(1, …)` 夹成 1 ——
`/attempts` 与 `/items` 列表都会只回一行。这个 bug 是**新写的题库测试抓出来的**，已修。

**G5 · 账户面板一直是裸 DOM（既存缺陷）。**
`account-panel.css` 从没被任何模块 import —— 面板与账户切换器的样式全部没生效。只因为此前我只核对了
面板的**文字内容**、没看观感，一直没发现。已修（静态 import）。

**G6 · 启动时不推送 → 审核标记进不了库（上一轮修，本轮验证）。**
现在用户账户里已经有 **394 条审核标记全部 `ok`**，`revision 1`。此前 `revision 0` 意味着一条都没进。

## 三、还没接通的（诚实列出，不假装完整）

- **N1 · 真正的"定制"：按你的答题情况即时生成下一课。** 这是最大的缺口，也是最初的方向。
  现在只有"离线批处理 + 人工审核"，**没有"读你的错因 → 生成针对性题目"的回路**。
  已具备的基础：语料检索层、出题脚本、模型富化脚本、LLM 客户端（`scripts/llm.py`）、
  账户题库（题可以按账户存）、错因标签（`Attempt.errorTags` 已有数据）。
  缺的是：把这套搬进**服务端**（Node 里调 DeepSeek，或 server 调 Python），做一个
  「读 evidence + errorTags → 选目标 → 检索语料 → 出题 → 富化 → 写进账户题库 → 进队列」的端点与界面。
- **N2 · 真实登录 / 多设备。** 现在没有服务端，账户只是"本机单人、多套数据"。要做登录需要把库放到服务器上。
- **N3 · 错因驱动补练**（答错后下一题锁定同一错因的最小对立）——仍是排期项，数据已具备。
- **N4 · 题库总览界面。** 现在能在审核页逐题定版、在面板看按思维点的分布与批次，但还没有
  "按批次对照两批题"的专门页面（CLI `python scripts/db.py items` / `batches` 已可用）。
- **N5 · s4 只富化了 40/400。** 那 360 道**没有模型过过释义与纠正**，所以本轮没有导入
  （宁缺勿错：没富化的题会缺逐项纠正与判据）。要更多三单题，应当重跑 `enrich-items.py` 而不是硬导。

## 四、用户那三句话的直接回答

1. **「生成的题库都应该是定制的」** —— 对，但目前只做到"**属于账户**"，还没做到"**按你生成**"。
   已落地的是：题库是账户内容（`items` 表 + `/api/accounts/:id/items` + 抽题池合并 + 逐题定版入库）。
   "定制"（按你的错因生成）见 N1，是下一步的主要工作。
2. **「可对照的」** —— 有了：每次导入/生成留一条**批次**（谁生成的、多少道、什么备注），
   `python scripts/db.py batches` 可对照；面板里也能看到按思维点的题量与信任级别分布。
3. **「保存在账户里」** —— 做到了，而且**清空进度不会清掉题库**（有测试）。
