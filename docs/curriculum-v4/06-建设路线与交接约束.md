# 建设路线、个人路径与开发交接

> **2026-09-30 修订：阶段 C/D 的供给方式以 [11 按需生成与自适应课程 PRD](11-按需生成与自适应课程PRD.md) 为准。72 单元是范围和目标账本，不要求预先写完 72 套固定课程。以下原文仍可追溯，但与 11 冲突处由 11 覆盖。

日期：2026-09-30。范围是规划，不是开发或部署授权。本版不修改应用代码、不迁移学习数据、不调用生产内容生成、不向其他 agent 发消息。

## 1. 对现状的判断

四轮代码审查主要检查可靠性和内容管线运行。它们不能证明课程完整，也不能证明重复题能带来真实进步。这次产品目标必须独立验收。

本轮静态抽查可确认：
- src/data/course.ts 的正式组织仍主要是第 7、10 课，另有深度阶梯样板与主宾格试用题；声音与词义模块是空 lessons 的建设中入口。
- src/data/ladder-demo.ts 明确是一个主宾格知识点的 18 题样板。加题型和阶梯仍不能替代全范围内容。
- src/learning/ladder.ts 存在累计尝试达到题量三倍即放行的机制。防卡死应保留，但不能把这种放行显示为掌握；更不能据此给成人真实的能力成就。
- src/content/bank.ts 的去重围绕题面/句子，无法独自处理“换名字、换词但练的能力完全相同”的语义重复。
- docs/curriculum/corpus-coverage-spike.md 的 2–8 词过滤适合当时的局部探索，不能作为完整系统的全局语料限制。
- 样板解析存在将不合法形式解读为另一种合法含义的情况，详见 02。教材事实审查必须独立于接口/状态机审查。

以上为文件证据，不是本轮生产环境、全部题库或个人账户的统计审计。不沿用源码注释中的百分比作为最新实测数字。当前线上到底剩多少未做题，仍需另做授权范围内的只读数据盘点；这不影响课程方向的判断。

问题集中在五处：内容范围太窄；变化未带来新能力；评价偏识别而弱真实运用；缺少清楚的后继内容；解释缺乏边界核验。仅增加题数、改抽题权重、增加六层进度条都不能单独解决。

## 2. 个人的 18 个月方向

用户预计约一年半后开始申请，不等于一年半后入学。没有当前托福考试计划。课程先支持英语能力与作品交流，学校考试要求将来确定时再接入，不反向改成应试产品。

以下是待诊断调整的时间窗口，不是固定成绩承诺。用户无需按月重刷已经掌握的内容；全图覆盖和个人免修记录并存。

|时间窗口|重心|看得见的阶段成果|
|---|---|---|
|第1个月|诊断、适应新机制、打通熟词声音与自主表达|建立基线；能说明自己的作品并完成几轮生活问答；找出主要阻点|
|第2–4个月|按缺口整合基本结构、时间、情态、连接与常用Chunks|对熟悉领域能连续解释原因步骤，听短讲授并有效澄清|
|第5–8个月|关系从句、非限定、条件让步、篇章关系与连续听力|能读听更复杂材料，概括主张和限制，讨论不同方案|
|第9–12个月|信息组织、压缩、隐含关系、高级边界与长段输入|能处理新研究材料，写清楚的提案并参与讨论|
|第13–15个月|四技能综合项目、全范围查漏|用陌生材料完成听读讨论写作，核查高级及低频目标未被遗漏|
|第16–18个月|作品陈述、面试追问、学校相关真实材料及剩余缺口|形成可比较的作品说明和访谈记录；清楚知道仍需提高哪里|

每两周用同等条件的陌生任务看趋势，每月回看目标和时间分配。不是每两周给所有人同一张测试卷。真实能力增量不明显时应调整教学和材料，不能建议用户单纯再加学习时长。

用户的首要出口是能听课、互动、回应、表达，允许自然停顿和有目的的澄清。不能承诺“所有美国场景零停顿”。保留完整语法覆盖，同时把日常/学术任务作为使用证据。

## 3. 建设顺序与完整交付边界

### 阶段 A：范围与合同先定下来

本次已提供全课稿映射、参考范围、72 单元/216 目标组、概念前置关系、教学流程与跨阶段脚本。下一生产批次首先细化参考页节台账和各目标边界。

验收：每个单元有可观察出口，每个目标有教学去向；细则台账的空项显式存在。不能把“章级映射已完成”写成“全部语法细则已验证”。

### 阶段 B：校准教学，而非另做一个长期 demo

用 05 的基础、中层、高级、综合四类脚本制作小批可实际使用的内容，含真正可播放的音频、独立口述/写作和反馈。试用目的是发现机制问题，同时推进其余单元的内容合同；不能将全课程建设无限延期。

验收：成人能跳过已会层；至少一段能体现难度增长；声音/结构缺口能分流；陌生输出可评；错误解析无臆造；高低阶段均能运行。必要时在实施界面前先以人工组织学习会话验证。

### 阶段 C：按个人路径滚动生成与校准

先固定全图目标与质量合同，再由后端按学习者当前证据生成近期连续课程窗口；每次学习后重算目标、材料、策略与难度，按需补充后继、支线和保留测评。月度看覆盖账本、生成可用率、陌生迁移和内容弃用率，不按生成了多少字符串验收。

所有 72 单元都在覆盖和可达范围；分批按需生成不是删除后半课程，也不要求提前预制 72 套固定课。每个目标需有可生成、可校验的教学合同和未满足事项；实际课程实例按个人路径产生。具体生成时延、质量、内容弃用率、模型成本与人工复核负担须通过真实试产测量，不能凭目录给出固定完工日期。

### 阶段 D：实现自适应学习产品

在上述合同支撑下实现学习者画像、目标重规划、后端按需生成、策略版本与回退，并改入口定位、证据、斩掉机制、开放回答、音频和成长展示。尽量复用现有账户、版本、作答记录、审核与存储。界面不应暴露工程管线作为学习主流程。

验收：具体用户旅程通过，而非只有单元测试绿。看阶段出口、重复率、提示依赖和内容供给，保持旧的账户隔离/版本一致性要求。

### 阶段 E：完整性审计与持续更新

只有参考细则全部有去向、每个正式目标都具备可达的生成合同且不同复杂度的生成质量经过真实验证、综合出口可运行，才能宣称该版本具备全范围按需教学能力。这与“72 单元全部预制上线”和“用户已全部掌握”是不同状态。新材料发现遗漏时扩展版本，不塞进一个无限的“其他高级语法”篮子。

## 4. 旧题和历史如何迁移

先建立旧 skill/question → 新 K/U 的映射及用途。按类别处理：
- 正确、目标明确、有价值：进入导入、定向补练或可用家族。
- 正确但同质：保留历史，减少主动推荐，不把不同 ID 当新能力。
- 解析失实、来源不明或答案不稳：从认证池撤下，修订后保留版本链。
- 跟读、看答案后成功、自评：保留其真实身份，不升级为独立口语能力。
- 已做的旧基础题：成为诊断线索，不能一键转换成高级节点全绿。

迁移先在独立数据副本验证，不触碰原库。采用何种数据库表与运行格式属于后续实现设计。本目录 JSON 是课程规划数据，禁止直接导入运行时作为 reviewed/published 题目。

旧“标签只提示不阻塞补齐”是旧纠正管线取舍；不能由此推导新课程可以没有目标 ID、家族 ID 或评价条件。两者解决的问题不同。新内容认证所需元数据必须齐全。

## 5. 对下一个开发 agent 的约束

先读 [00 总 PRD 导航与开发路径](00-总PRD导航与开发路径.md)，再读 [13 完整产品 PRD](13-完整产品PRD-需求与验收.md)、[14 首条旅程](14-首条端到端旅程与分流规格.md)、[15 实施合同](15-可直接开发的实施合同.md)，按其中的文件职责与阶段门槛查阅 08、11、12、02、03、04、05 和本文件；需要原课依据再查 01 与 sources.json。用户已确认的个人事实不再逐个询问。

优先级：用户最新明确要求 > 本版需求记录与合同 > 旧 PLAN 的局部开发顺序。旧部署、账户、数据保护约束继续有效；这里不授权上线。

禁止：
- 缩回“先生成几百道主宾格题再说”。
- 用更长句子、更多选项或题号增长冒充难度/知识增长。
- 因输入中出现某概念就把它记为该能力被检测。
- 把自评、跟读、ASR 成功或模型自夸当独立能力认证。
- 次数够就标掌握；斩掉后再无条件安排同级复习。
- 把课程草稿、已审核、已发布和用户掌握合成一个状态。
- 因没有新内容而无提示地循环旧题。
- 把所有缺口归语法，或者把完整语法覆盖直接等同四技能全面达成。
- 声称这些原创教学是张俊杰本人制作或认可。
- 为显得解释统一而编造语言历史或“每个错误其实都在表达另一个意思”。

## 6. 必须通过的用户旅程

|用例|通过条件|
|---|---|
|成人会基础|短诊断或免修后直接进入合适复杂度，不要求刷完基础库存|
|文字懂声音卡|阅读不被重置；听力支线有相应任务|
|已会层斩掉|日常队列无该层同质题，后续复杂组合仍可出现|
|连续错误|得到归因和短修复，不以多错自动认证|
|提示后成功|显示训练完成，陌生独立证据另收集|
|自由回答不同参考|语义正确且满足目标可接受|
|题目争议或转写失败|不给用户错误降级，明确待确认|
|长句角色/否定错|反馈定位哪一层关系，不能被总分掩盖|
|内容耗尽|诚实显示已完成可用范围与下一步，不伪造新课|
|版本更新|历史可追溯，不跨账户、不凭空清空已完成内容|
|全程完成|听说读写都有独立出口；低频高级目标有完成/免修证据与检索去向|

## 7. 第一轮真实试用如何判断有没有用

先用两周小范围个人试用判断设计是否需要调整，不以 N=1 宣称普遍有效：
- 基线与后测使用不同家族、相近目标和难度；保留原始口述/文本及条件。
- 看漏听后能否恢复、主干与逻辑是否准确、无原稿能否自主表达、提示是否减少。
- 看用户是否知道今天增加了什么，是否仍感觉同一道题变着花样出现。
- 按预先量表复核至少一部分开放输出；记录评分分歧，不能只看模型分数上涨。
- 若只在旧题上变快、新任务不进步，视为迁移不足，需要改材料和组织。
- 若识别分数高但口述仍卡，保留已会的理解层，增加检索与真实互动，不降回基础选择题。

两周并不能证明长期保持；之后继续收集至少数周的延迟与跨场景证据。长期目标看季度综合作品与陌生互动表现。

## 8. 真正需要用户参与的下一刻

现在不再追加泛泛偏好问题。下一次请用户参与，应带着具体任务或比较结果：
1. 有可用的首轮诊断材料时，收集一段实际口述和一段文字，确定起点。
2. 有两种反馈/讲解版本时，让用户体验后比较，而不是空问喜欢哪种。
3. 要接入用户已有 Chunks 教材录音时，再确认具体资料和使用范围；当前未导入。
4. 需要选择付费语音/模型方案时，先给功能、费用测量和替代方案，再谈预算。
5. 学校项目确定后，再补相应真实材料与申请要求。

这些是后续协作节点，不是本轮工作的阻塞项。当前规划已经可以审阅并用于内容工程；具体成效、起点和参数必须通过实际学习校准。
