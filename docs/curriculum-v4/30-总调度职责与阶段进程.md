# 总调度职责、阶段进程与验收规则

2026-10-01｜用户明确指定 Codex 为总调度，Zcode 为实现者

## 责任归属

Codex 对方向、优先级、依赖、复审结论和下一批安排负责。Zcode 对代码、测试、内容接入、页面实现和实施证据负责。双方都不能把测试全绿当完成所有产品要求。总调度必须回答：现在在哪、下一步是什么、为什么这样排、什么证据才算完成。

总目标保持用户原要求：以张俊杰21课的结构解释思路为起点，补齐全范围知识地图，后端按个人学习表现持续生成课程，逐步改善真实听说读写和课堂/生活交流。学生应体验一条清楚、具有挑战与成长反馈的学习路径，而非后台诊断面板或固定几百道题。

## Codex 每轮必须完成

1. 读取 STOP、双方信号、未审结果、当前任务、动态账本；先确认能否推进，等待时不重复跑测试。
2. 校验交付 commit 与实际差异，确认受审代码稳定；不代改/提交 Zcode 工作。
3. 按任务验收，再核实对产品目标的影响。关注数据真实性、材料事实、教学节奏、正常页面路径、连续后继和自动适应；一次通过不能自动等于后续阶段通过。
4. 已修问题关项；新问题写触发、影响、来源、最小修正方向与验收。不要求镜像测试、无关重构或为耗额度反复审同提交。
5. 给出 accepted/changes_requested/needs_snapshot/blocked，并发布有范围、依赖、交付、验收的下一任务；将阶段状态更新到 reviewer-owned orchestration-status.json。
6. 督促 Zcode 更新 implementation-status.md 的实现与证据，校准“已实现/已验证/本人试用/效果已知”。不能让旧顶部与新分解表互相矛盾。
7. 对已授权范围直接推进。需本人实际反馈、真实人审或其他不可替代输入时记录 awaiting_user，继续其余不依赖它的工作；不伪造完成。
8. 每个阶段至少取得一次完整正常路径证据，不能一直收紧拒绝门却没有学生可用路径。

## 阶段顺序与总调度责任

|阶段|当前判定|总调度如何推进|
|---|---|---|
|D0 可信合同|进行中；首轮存在 partial 实际升级缺口|任务000002先收口，随后统一issuedTask/请求/播放/录音/测量支持；含存量纠正和正常路径|
|D1 学习者旅程|当前只有开发框架；28原型已派入000002|与D0同步交付可点击入口→训练→反馈→下一步，再接3节完整内容与真实材料；不等所有后台完工|
|D2 个体滚动生成|框架存在，个体教学效果未验|通过3类根因快照差异、缓存作废、审核与失败回退证明真正适应；低库存按需补课|
|D3 本人可用性|未正式完成|开发先走完整路径再邀请本人短程体验；记录难度、理解、输出、反馈与重复问题并改下一批|
|D4 正式效果观察|机制不完整、新留出材料缺|预注册→正常首测→后测→延迟，条件与版本可比；N=1不夸大推广|
|D5 全范围扩展|633条AI草稿，尚非事实核验完成|沿近期路线及相邻前置/后继逐块核验；持续更新全范围台账，不停在which，也不全量盲生成|

实施细则以27为主，学习体验以28为主；26/29及自动reviews是缺陷与验收记录。新增文档不另造一套路线。每批只选可审阅的工作量，重大合同与页面/内容可分提交但交付依赖清楚。

## 任务与并发控制

总调度是 tasks 与 reviews 的唯一发布者；Zcode 不自行跳到未派发阶段。已ready的任务不可静默改写，新要求走附加指令或下一task。Zcode收到新协议职责后在下一结果中确认读取，无需再经用户转贴。

结果已交付至复审结束，Zcode不继续改受审文件。未提交漂移先要求稳定快照，保留其他人的改动。超时锁不能只因25分钟就抢占正在运行agent，须确认失活且无活跃写入；无法确认只报告，不启动第二个编码任务。

网络重试不是新作答；暂未测量不是失败；播放交互不是听懂；选择定位不是开放表达；AI草稿不是事实已审；原型不是上线；设备可用不是效果有效。以上由总调度每轮守住。

## 完成、停止和交接

无人值守可以完成已授权的开发、验证、材料整理和原型；不能自动替本人体验或真人事实审签。项目“完整”的状态要分别列功能、覆盖、材料、个人验证四项，不设一个虚假的总完成百分比。

硬额度耗尽、STOP、权限阻断/连续三次同一不可推进阻塞、无可推进事项时保存已完成/当前版本/待审结果/下一任务/外部依赖并停调度。不充值、不自动等额度重置续跑，不擅自部署。用户新指令可恢复。

通知只在新阶段交付、真实阻塞、需要本人或结束时发送；正常等待不刷屏。任务000002已经发布，先等待其结果，不另起重叠任务。
