## 必修问题（A批：数据与事实口径）
### R1 / P1：普通状态接口能伪造新题验证通过
server/toefl/api.mjs:errorStatus，server/toefl/toefl.test.mjs的状态机用例。
复现：pending_review→reviewed→awaiting_new_check后，POST status=verified且只有任意detail，返回200/verified；无新题、无新作答也写passed记录。现有单测反而把此绕过当成功案例。
要求：普通状态更新拒绝verified。只能由服务端验证流程计算，绑定新题attemptId、内容版本、独立/精学模式、曝光/支持条件、结果与目标。无未见池时永远不能获得verified。
验收：同样三次请求最后409；不能靠改detail通过。正向用隔离已审题集验证不同新题证据，不改真实账户。

### R2 / P1：反馈失败使课程进度倒退，两页面口径不一致
server/toefl/content.mjs:computeProgress只接受status=submitted/analyzed；requestFeedback改成analyzing/failed。chapterState却按submitted_at看实践完成。
复现：听力提交后单科done=1；失败桩返回502后done=0。作答还在，却被首页扣回进度。
要求：提交事实与反馈运行状态分开；活动完成依据稳定的提交事件/时间，不依赖AI成功。首页/课程页共用章聚合规则。失败、进行中、重试都不能抹掉已完成活动。
验收：提交→分析进行中→失败→重试成功，实践一直完成，两个页面一致。

### R3 / P1：保存稿升级提交会清空原稿，重做没有新尝试
server/toefl/api.mjs:submitAttempt，src/toefl/ToeflApp.tsx:PracticeTab。
复现：保存“Do not erase this original draft.”后同键submit:true、不带draft，返回draft=""。因为str(undefined)变空串，再覆盖已有稿。
前端每题组固定s01-task-account幂等键；提交后的再次修改/提交只会重放旧attempt，不是新的练习稿。只保存草稿却调用onSubmitted切到复盘，体验也错。
要求：区分字段未提供、明确清空、内容修改；保留首稿，重做/反馈后修改建立新attempt/revision并关联父尝试。一次操作重试复用键，新学习尝试用新键。只保存留在练习并提示成功。
验收：保存后省略稿字段提交不丢；明确清空按规则处理；修改版有独立记录并能对照首稿/反馈；反复点同一次提交不重复。

### R4 / P1：空答可提交并领取答案，空口语也可提交
server/toefl/api.mjs:sanitizeAnswers/submitAttempt。
复现：封闭answers={}提交200，随后GET返回全部key；口语无音频无文字提交200。只在React按钮禁用不够。
要求：提交时服务端验证本组所有合法题ID、每题选项范围；缺题、越界/未知题按明确规则400且不落提交事实、不泄答案。草稿保存可以不完整。口语至少有成功存档音频或本人文本；保存→提交也用同一验证器。幂等键与任务绑定，不能同键跨任务升级。
验收：直接API空答/漏答/越界/未知题/空开放题均拒绝；合法完整提交后才有结果；保存与提交两条分支都覆盖。

### R5 / P1：所谓版本化目前只是读当前JSON
server/toefl/db.mjs没有Attempt内容快照/版本、计划冻结字段；attemptResults与buildTeacherInput重新读取当前task；Feedback只有递增序号，实际模型统一写server-llm。
目录catalogVersion和planVersionNote不是历史冻结实现，loadJson甚至按文件长度缓存，同长度修改可能读旧内容。
要求：先建立内容版本与题面/答案/任务快照、账户计划版本、尝试/反馈/音频版本绑定；历史解析不可随JSON改写。记录实际模型和配置版本。目录缓存使用可靠revision/hash。
验收：提交v1后发布修改版v2，旧答案/解析/AI输入保持v1；同长度改动不能缓存漏更新；扩章时旧计划分母不静默变化。
此项须在扩建正式发布前完成，避免以后无法挽救历史记录。

## 必修问题（B批：本人能继续学）
### R6 / P1：继续按钮不恢复阶段和视频位置，首页又不刷新
src/toefl/ToeflApp.tsx:CoursePage默认learn，不读取resume；load立即写当前tab。LearnTab给播放器startAt=0；播放器只上报media-progress，不写resume位置。
API复现：先保存42秒，再按页面同样course_open请求省略位置，resume变成mediaId=null/lastPosition=0。
另外根组件loadDashboard只在初挂载/档案保存/错题操作触发，课程完成/反馈后回首页仍显示旧data。
要求：先读指针再渲染/写入；分科/章/媒体独立，省略字段不清空；离开前保存播放位置。回首页重新聚合，或用一致的数据缓存失效策略。后台拉取结果不能覆盖已切换对象。
验收：阅读停复盘、听力停42秒、写作有草稿→切科→刷新→分别恢复；课程提交/复盘返回首页立即更新。不能仅测API“resume可写”。

### R7 / P1：录音上传实际上没有路由，且存储不在持久卷
saveAttemptAudio/readAttemptAudio函数存在，但TOEFL_ROUTES没有注册；middleware识别raw body也不代表完成处理。
复现：对合法口语attempt PUT /audio返回404 no such endpoint。
前端回放只有recUrl，刷新没有取回已有录音；录音上传没有完成状态屏障；切科/卸载缺清理。文件默认server/assets/toefl-attempts，compose持久卷只有/app/data等，没有此目录专用挂载；TTS文件也在镜像目录。
要求：账户范围上传与读取路由、MIME/格式校验、录音引用/版本、刷新回放；上传完成再提交，失败可重试不丢blob；离开停录并释放麦克风，明确失败状态。将学习音频放配置化持久目录并准备备份/恢复，不执行生产部署。
验收：真实浏览器录一段→上传→刷新/另一客户端回放；失败后保留重试；容器/进程重启后仍可读。硬件录音若不能测试须明确边界，不能用文字稿替代“录音已验收”。

### R8 / P1：跨科页面可能串草稿与老师反馈
CoursePage换part不重新建立实例，LearnTab/PracticeTab/ReviewTab用useState一次初始化；ReviewTab新科无反馈时没有清除旧fb/audioUrl；旧请求也没有取消/对象校验。
这是静态代码确认的风险，本轮未启动浏览器复现，不写成已运行结论。
要求：按account/chapter/task/attempt标识分离组件状态或显式重置；异步响应绑定请求对象与序号；首稿、笔记、音频、老师反馈不串科。
验收：A科已有老师分析，B科无反馈→切换不能显示A；快速来回切、迟到响应、账户切换均隔离。

## 教学质量问题（C批：老师拿到完整任务，再推进课程）
### R9 / P1：真实调用通了，但老师缺完整原文/题目要求
teacher.mjs:buildTeacherInput阅读/听力只给选项和支撑句，没有完整阅读正文或已审音频稿/片段；开放题只给material.prompt摘要。

要求：真题完整任务文字入库（原文/全部要点/题目/选项/来源页），老师输入引用该版本；听力用审校全文/时间段并标可靠性；无稿不推断声音问题；口语各采访问题单独明确，不能泛评整段。
验收：写作样例“只写故障求助、遗漏另两要求”必须指出任务缺项；符合全部要求的稿不能被错误扣任务完成。四科各做正答/错答或完整/缺项/自述异议的质量抽样，不重复无意义大批真调用。
