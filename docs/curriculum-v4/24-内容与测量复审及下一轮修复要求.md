## R1 · P1：逐目标映射在判题过程中被丢弃

位置：[v3evidence.mjs](../../server/v3evidence.mjs) 141、151–164 行。

relScans 中的原始关系有 objectiveIds，但转换为 relations 时只保留 id/label/required/hit。随后 tagOf 对这个简化对象读取 objectiveIds，永远回落到活动的全部目标。这样“逐目标判定”仍会把所有关系混在一起。

复现：活动含 A/B 两目标，alpha 关系只归 A、beta 只归 B。只答 alpha，实际返回 A=partial、B=partial；应为 A=met、B=unmet。这会把已会目标判弱，也把未答目标算部分会。

修复：用原始关系归属计算结果，或在内部中间对象保留归属；不要求把内部评分合同公开给学习者。没有归属的旧题必须显式迁移或标为未对齐，不能默默认定全部适用。对既往受影响事件作可追溯纠正/重算。

验收：A 单独正确/B 错误、相反情况、共享关系、未测目标、某目标违规而另一目标正确，分别验证。要断言各目标，而非只断言整题 pass。

## R2 · P1：按策略兜底仍会给与主目标无关的课程

位置：[v3plan.mjs](../../server/v3plan.mjs) 294–315 行；[v3lessons.mjs](../../server/v3lessons.mjs) 320–336 行。

finalize 先找主目标，找不到仍 lessonForStrategy，后者没有目标约束。轨迹本身已复现：第 4 步推荐 O-K007-01，却发 les-disposable-v1，实际活动 ct01/ct02 只测 O-K115-02。这只是没有复推旧课，不能证明推荐路径正确。最终无课还返回 les_l1_sensor_read 的 fixture 活动，脚本自行将其称为诚实缺内容态；应检查真实 UI 是否会把它继续展示成下一题。

修复：所有推荐和窗口检索共同校验主目标、技能、任务难度、策略及适用条件。无主目标课程就 content_pending；若确实决定先练其他目标，应改变决策目标、说明前置原因并校验依赖，不能用无关课填空。

验收：轨迹逐课断言 decision.primaryGoal 属于课的实际可测目标；课/活动与推荐技能、复杂度匹配。免修后立即重算并断言其不再推荐，不能只检查 flags。不能因为策略相同就借另一课。

## R3 · P1：关键词和否定补丁仍不能判断关系是否成立

位置：[v3evidence.mjs](../../server/v3evidence.mjs) 109–178 行；[v3-activities.json](../../server/data/v3-activities.json) ct03_semantics_guard。

真实评分器复现两种错误答案，均 pass=true、O-K115-03=met：

- “手势 语音 多人 仍想”——词袋，没有任何决定或因果关系。
- “他们搁置手势，采用语音，因为多人同时说话，仍想探索。”——与原文决定相反，只换了反转表达的同义词。

当前 kept_gesture 的锚点只是手势，hold_voice 只是语音，否定窗口和几条禁词无法证明“谁保留谁暂缓”。官方少量候选通过，不代表开放语义验收通过。

修复：受控活动可改成独立的角色/动作/原因槽位与关系选择，再检验开放复述；开放回答若无可靠独立语义评估，只给练习反馈或 disputed，不写掌握正分。不要不断补 mustNot 同义词冒充语义理解。生成合同也不应强制把 anyOf 关键词当完整评价合同。

验收：正确改述与反向动作同义改述成对测试；词袋、主体互换、错误因果、矛盾前后句、否定范围和部分答案。只有实际可判的关系才写目标证据。

## R4 · P1：有音频引用即视为听过，未播放也产生听力进度

位置：[v3evidence.mjs](../../server/v3evidence.mjs) 326–346、431–434 行；[v3audio.mjs](../../server/v3audio.mjs) audioPublicInfo；[V4Path.tsx](../../src/components/V4Path.tsx) 366–371 行。

隔离数据库：提交 les_l2_museum_map_audio 的正确文字回答，playCount=0，没有请求或播放音频，返回 200/pass=true，两目标 listening 的 band4 和 base 均 trained。前端未播放也默认 playCount=1（?? 1）。状态只看 audioRef，未核实际播放条件。清单行存在就可展示 audio；文件缺失/损坏的分发检查没有进入证据门，因此 23 所称“文件损坏挡证据口径”不成立。

修复：播放器未播放计 0，未完成最低有效输入不给听力正分。音频分发完整性/许可/版本验证结果与任务绑定；服务器保存任务级播放/字幕支持事件，客户端事件只能作为可观察交互证据，不能声称能证明人真的听懂。文件不可用时明确未测或替代阅读。音源类型取 manifest，不把所有 audioRef 硬标 synthetic。

验收：零播放、加载失败、悬空清单、坏哈希、看稿再答均不能获得独立听力；正常播放可产生受限定证据；界面刷新不能清空既有支持记录。历史重算用作答时材料版本/模态快照，不能因为后来给旧活动添加 audioRef，就使过去文字成绩变成听力。

## R5 · P1：网页答错后无法再试，与报告轨迹不一致

位置：[V4Path.tsx](../../src/components/V4Path.tsx) 366、430 行。

文字活动 attemptId 固定为 lessonId+activityId，提交后按钮只要有 feedback 就禁用。学生即使改答案或看提示，也没有新一轮提交入口；绕开禁用会因同 ID 异正文得到 409。trajectory-walk 的“失败→重试成功”使用自行创建的新 ID，网页没有对应流程。

修复：明确“看反馈/提示→再试一次”，新作答用新 take ID；网络重试沿用同一次 ID，区分传输重放与学生再次作答。旧答案和反馈保留，提示条件不可重置为独立成功。已有口语重新录制按钮本轮不再视作缺失。

验收：实际网页上先错、看提示、改答、成功，再完成课；正常刷新/网络重试不重复入库。必须有浏览器走查证据，API脚本不能替代。

## R6 · P1：复杂度槽位取目标组固定等级，不能记录同目标不同难度

位置：[v3evidence.mjs](../../server/v3evidence.mjs) 346、375–379 行；[v3oral.mjs](../../server/v3oral.mjs) 人审事件。

complexityBandFor(objectiveId) 取目标父组 complexity_band，未取本次活动难度。CT01 简单 which 对比和 CT02 嵌套 which 都进入同一 O-K115-02/band4；这两题即可累积 independent。真实槽表虽然已经有多带，但正常记录路径对同一目标总是同带，无法实现“简单会、嵌套不会”。插入人工多带事件的测试不能证明真实产品可达。

修复：目标地图等级与任务复杂度分开。活动版本声明可核实的复杂度/关系负担/支持条件，事件保存该任务快照；机器和人审共用。base 聚合含义需明确：仅覆盖已测带的概览，不能表示未测高级带已掌握。推荐要读具体缺口带。

验收：同目标简单正确、嵌套错误落不同槽；简单独立不等于复杂独立；后续补复杂任务成功仅改变对应带；真实提交端到端验证，不能只往事件表手工塞行。

## R7 · P2：试学材料绑定仍可省略，陌生性只检查答过没有

位置：[v3trial.mjs](../../server/v3trial.mjs) 41–54、96–119、126–150 行。

注册仍不要求 activityId/materialVersion/passRule；核对版本仅在字段存在时执行。materialRef 可以是任意描述，未绑定实际发题。曝光查询只检查同 activity 的既往作答，不包含已经看过/听过但没提交、同任务改名或公开样板；同条件判断也未检查技能、难度和量表一致。

修复：正式测量模式要求版本化材料/量表引用和匹配技能/难度；宽松旧注册仅可练习记录。发题/声音/提示/稿件曝光建立记录，已公开材料不作本人留出。未知是否曝光则未知，不能自报 true 就正式计入。不同家族应保留等能力、等难度，不能只因标签不同认定可比。

验收：缺版本注册不得正式计入；已取题但未答后重复做不算首见；同稿换 ID 可识别；量表或技能不同只展示、不构成同条件比较。新留出题仍待生产，不能拿 18/21 的公开样例补上。

## R8 · P2：口语 playable 标志仍未证明音频有效

位置：[v3oral.mjs](../../server/v3oral.mjs) 50–68、166–184 行；[V4Path.tsx](../../src/components/V4Path.tsx) 546 行。

storeOralAudio 接受任何非空字节即 playable=1；UI 时长仍传 0。人审检查数据库 playable，却不确认文件仍在、格式可解码、真实时长。前轮修好的账户、attempt 绑定和内容门值得保留，但不能把这一位标志当真实录音验证。

修复：上传验证真实格式和时长；不可确定时仅存草稿待设备/人工确认。签署时再次检查媒体可读与绑定快照。非法目标列表应全部预检，再事务写签署/事件，避免前几个已写后后一个抛错。人审不应仅凭活动条件 firstExposure/hintLevel 把已看稿、查词的口语归独立。

验收：随机字节、零时长、删除文件、部分非法目标、看稿口述均得到正确状态；真实设备录音回放成功才进入签署路径。
