# 万词班单课接入：从视频到贯穿式记忆

本技能是第一课（cfcm-01-01）实际走通并经四轮外部审计后固化的流程。它负责编排和把关；转录与逐词讲解的具体工艺在 `local-course-transcript` 技能里，本技能不重复。

目标只有一个：**学习者上完课后，知道每天该做什么，并且学过的词不会在第二天之后断线。** 内容做得再全，如果第 1 天、第 3 天接不上，这一课就不算接完。

## 先读

- [学习闭环与调度规则](references/learning-loop.md)：这一课接入后学习者每天看到什么、每个按钮如何结算。改任何调度或入口之前必读。
- [验收清单](references/acceptance.md)：每一阶段过关的判定条件，来自审计中真实出过的问题。
- [第一课基线与已知缺口](references/lesson-01-baseline.md)：第一课的实际数字、文件位置，以及接下一课前必须先处理的单课硬编码。
- 项目规则：`toefl-lab/AGENTS.md` 与 `toefl-lab/docs/deployment-authorization.md`。

> 本技能的权威副本在仓库 `toefl-lab/skills/cfcm-lesson-flow/`；`~/.agents/skills/cfcm-lesson-flow/` 是让 ZCode 能自动加载的镜像。改内容只改仓库这份，然后整目录复制过去同步。

## 边界

- **一次一课。** 只做用户点名的课；流水线可复用不等于可以批量预做。
- **用户已上过这节课才接。** 主线是"先上课，再认读"。没上课的课可以先备内容，但不发布入口。
- **不碰个人学习数据。** 不读、不导出 `records.json` 明细；不在生产环境替用户开始会话或评分。验证用隔离的测试记录。
- **不编老师的话。** 没有讲解价值就留空；老师讲解、基础释义、词源关系三层分开存，分开标注。
- **同一个词只有一份长期记忆。** 跨课重复词复用已有词键，只追加来源，不重建状态。
- 原视频、讲义、原始转录、已交付逐字稿只读。

## 阶段

每个阶段结束都对照 [验收清单](references/acceptance.md) 的对应小节，过了再往下。任何一步没过，停下来报告，不带着缺口继续。

### 0. 定课

确认课次、lessonId（`cfcm-01-NN`）、视频文件和讲义页范围。注意"最终季"与"往期18节"有同名课，不能混用。确认用户已上过这节课，或明确只是备内容。

### 1. 逐字稿

按 `local-course-transcript` 技能的主流程执行到 deliver。产物在 `课稿-校对版/万词班最终季/第NN课/`。如实记录是否做过人工听验。

### 2. 逐词老师讲解与内容底稿

按 `local-course-transcript` 的阶段二执行：讲义每个列项落到五种状态之一，提炼有记忆价值的讲解，引文双源校验通过。

然后组装成内容底稿目录 `课稿-校对版/万词班最终季/第NN课-词卡底稿/`，结构与第一课一致（整理说明、全词对应、可用讲解、补充词与待确认项、`04-词卡内容底稿.json`、manifest）。组装用 `pipeline/lesson_notes.py`（`annotate` → `assemble --deliver`）：课次事实——路径、别名、暂缓词表、引文 extras、叙事文案——全部写在本课 QA 目录的 `lesson-config.json` 里（含教师引文，留在 build/ 下不进仓库），工具代码本身不含任何课文。第一课的配置可照抄结构：`build/qa/cfcm-01-01-word-explanations-20261109/lesson-config.json`。

把统计数字报给用户（列项数、规范词数、有讲解的词数、暂缓数、未定位数），让用户先看一眼"可用老师讲解文字"再继续。内容是这一课质量的上限，这里值得停一下。

### 3. 词根投影

确认 `build/root-universe/learning/cfcm-NN/` 已有通过校验的当前版本（候选由 `pipeline/root-universe/prepare-cfcm-NN.cjs` 产出，每课一份作者式脚本；签署发布与校验在同目录的 `validate-kit.cjs`、`test-learning-release.cjs`）。词卡的词根标签、词根解释、同族词都从这里取。课堂助记关系与独立核验的词源事实要分开标注，卡片上不把前者写成后者。

### 4. 生成词卡

用 `pipeline/build_lesson_cards.py` 从内容底稿生成 `build/vocab/<lessonId>-cards.json`：

```text
python -I -X utf8 pipeline/build_lesson_cards.py --lesson cfcm-NN-NN \
  --content ../课稿-校对版/万词班最终季/第NN课-词卡底稿/04-词卡内容底稿.json
```

课号必填；输出路径、词根投影（`learning/<course>/current.json`）、默认标题都从课号派生，`--title`/`--learning` 可覆盖。已存在的词卡文件若属于别的课号会被拒绝覆盖。服务端启动时扫描 `build/vocab/*-cards.json`，文件就位即多一课，不需要改服务端代码。

生成后检查并报告：词数是否等于规范词数；有讲解的词数是否与底稿一致；没有音标、没有例句、没有词根的词各几个；别名词（讲义错拼）是否沿用旧词键；与已接入各课的重复词键清单。

### 5. 本地验收

1. 跑测试：`node pipeline/test_vocab_lesson_unit.mjs`、`node pipeline/test_vocab_lesson.cjs`、`node pipeline/test_vocab_client.cjs`、`node pipeline/test_vocab_api.cjs`。保存退出码。
2. 用隔离记录在浏览器里按 [学习闭环](references/learning-loop.md) 走一遍：第 0 天完整认读（含不认识、看卡、再确认、分段停顿），然后把测试记录的时间推到第 1 天和第 3 天，各走一次复习轮。桌面和手机宽度都要看。
3. 接入第二课及之后：额外验证横幅在多课之间的选择、课程页徽标、跨课重复词、旧背单词页不出现本课词。

"脚本通过"不等于"流程走通"。没有实际走过的部分，在报告里写明没走。

### 6. 发布

按 `deploy/README.md` 的例行发版和长期部署授权执行。要点：

- shell 脚本必须是 LF 换行（第一课首发因 CRLF 失败过）。
- 发布包要包含新的 `*-cards.json`。
- 发布前备份正式 records；发布后核对 health 版本、`/api/vocab/lessons` 列出新课且词数正确、该课会话为空（没有替用户开局）、已有课的会话和到期数没有变化。
- 同一工作树可能有并行会话在发版，发布前看一眼 `git log` 和 `VERSION`。

### 7. 交接与审计

在 `toefl-lab/docs/` 写 handoff（参照 `handoff-lesson-vocab-20261110.md` 的结构：不变量、接缝、已知缺口、请审计人回答的问题）。外部审计意见一律追加到 `docs/audit-lesson-vocab-*.md`，每轮一节，不另起文件、不等确认。修复提交信息里引用审计条目编号。

### 8. 使用回看

上线约一周后，从统计摘要（不读明细）看三个数，决定间隔是否要调：

- 直接认出的词，3 天后复习轮的认出率。很高说明间隔可以更长。
- 看卡后认出的词，次日的认出率。偏低说明当天循环还不够。
- 到期量最大的那天分几轮做完、是否做完。做不完就调单轮上限或放慢开新课的节奏。

结论和调整写回审计文档。间隔策略是用户定的产品决定，给数据和建议，不自行改。

## 最终回复要包含

接了哪一课、词数与有讲解的词数；哪些阶段实际走过、哪些只跑了脚本；发布版本；未决事项（未定位的词、暂缓的讲解、未处理的缺口）；用户明天打开应用会看到什么。
