## N1 · P1：封闭题仍然能靠全选和错序通过

位置：[v3evidence.mjs](../../server/v3evidence.mjs) 109–145 行。

choice 使用文本中是否包含正确 token 判分。ct03 输入 “a b c d” 通过；ct01 输入 “EVENT DEVICE B” 也通过，虽然前两空颠倒。三个活动输入 “A B C D DEVICE EVENT LAB POWER ASSUMPTION” 全部通过。mode=all 是集合包含，不是逐空全对；单选也没排除同时选错项。封闭分支还将一个 pick 赋给全部目标，未按问题/目标归属计算。

修复：定义独立 slotId、允许选项、正确值和目标归属，提交结构化 answers；单选恰好一个合法选项，多空逐槽判。缺空、多选、重复、未知选项需明确拒绝或判错。自由理由独立评估，不因选择对就认证原因和未测目标。

验收：全选、交换前两空、遗漏、多余 token 均不通过；单个槽正确只影响对应目标；开放理由有争议时不能因为选择对而整题认证。

## N2 · P1：CT02 题面串入另一课问题，并直接展示答案

位置：[v3-activities.json](../../server/data/v3-activities.json) ct02_nested_which。

材料是投影仪、实验室、电源与展出，却问“but 对照的核心判定是？ASSUMPTION（假设不完整）/ MAP（地图失灵）”。该段没有 but，也没有地图或假设，这属于 L2 的内容。题面例子 “LAB POWER ASSUMPTION” 又恰好是当前三空全部正确答案。学生照抄示例就得正分，不能作为独立能力证据。

修复：逐题核查材料—问题—选项—答案—原子目标；第三问替换为该投影仪材料真实可测问题或删除。格式示例使用不泄漏答案的占位符。检查 CT01 和后续自动生成模板，避免正确答案作为格式例子。

验收：所有问题均有对应材料证据；给未读材料者的题面不能直接包含答案序列；材料版本更新并撤销/更正受污染证据。不能只修字符串并保留旧掌握记录。

## N3 · P1：播放事件仍可在未读取音频时产生，关键词词袋仍记听力进步

位置：[v3api.mjs](../../server/v3api.mjs) 122–132 行；[v3evidence.mjs](../../server/v3evidence.mjs) 297–305、389–442 行。

临时库复现：不请求任何音频，直接 POST /support/play（活动与 mediaId 对得上）返回 200；再答“正常 假设 不完整 以为”，得到两目标 listening/trained。play 端点只查 manifest 行，不调用文件存在/哈希/许可检查。因此“坏文件无法产生播放事件”的结构断言不成立。一个播放事件永久可用于该活动后续版本，playCount 仍由客户端提供，服务器不是实际播放次数账本。

修复：播放上报绑定已成功分发且验证的具体材料版本/任务会话，分发失败不能写有效输入事件。它只证明播放器交互，不能证明人真正听过。词袋判题仍只是内容练习反馈：若保留参与度，单列练习/输入参与状态，不把它写成听懂目标的 met/trained。用可靠封闭理解任务或复核结果再写目标进步。

验收：无分发、坏文件、未授权、旧版本事件、过期会话不提供有效听力条件；仅词袋不写理解正分。播放失败可以重试，不能只给无法恢复的报错。UI 与 API 的 practiceOnly 含义一致：当前返回 practiceOnly=true，却仍生成能力事件，需消除此矛盾。

## N4 · P1：录音解析会接受没有声音的 WAV，WebM Duration 解析算法错误

位置：[v3oral.mjs](../../server/v3oral.mjs) 54–106 行。

复现 44 字节 WAV 文件头，声明 data 长度 32000，实际没有任何声音数据，inspectAudioBytes 返回 playable=true、durationMs=1000。解析只信 chunk size，没有验证 chunk 位于文件范围内，也没有校验编码/声道/位深/有效数据。

WebM 的 sizeLen=8-Math.clz32(sizeByte) 对合法单字节 VINT 0x88 得 -16。带 Duration=1000 的元素探针返回 webm_duration_unreadable。Duration 本身以 TimecodeScale 为单位，不是固定 ns；当前再除 1e6 的单位转换也不正确。浏览器 MediaRecorder 常不提供 Duration，当前没有可用确认/转码路径，不能称主流浏览器录音已经可用。

修复：用可靠媒体解析/解码方案，或实现有边界测试的格式解析；校验真实时长与上限。WebM 处理正确 VINT 与 TimecodeScale，缺元数据时提供解码测时/重封装或可实际完成的人工确认通道。不能只把用户录音锁成永久草稿。

验收：截断 WAV、伪 chunk 长度、无效 fmt、空数据不 playable；已知真实 WebM 样本的时长正确；至少一次真实浏览器录制→上传→回放→提交→签署全流程，不用手造 WAV 替代设备验证。

## N5 · P1：首次测验自己的播放/看题被当成既往曝光

位置：[v3trial.mjs](../../server/v3trial.mjs) 119–156 行。

priorSupport 查询同活动的任何支持事件，不按时间或任务会话区分。因此测验的正常首次播放也会让 exposed=true，measurement.counted=false。若以后给 holdout 正常取题写曝光事件，首次阅读测验同样会排除自己。它防住了旧材料，但也使正规首测难以可达。

修复：预注册、发卷、测验会话、有效首次输入建立关联。陌生性看正式测验发卷之前的曝光；本次测验内的第一次取题/听音属于施测，提示/重播作为支持条件记录。过去会话的曝光、训练中见过、公开样例继续不得算陌生。holdout=true 仅是标志，不能证明从未公开。注册时同时验证实际技能、量表/通过规则及任务难度，不仅比较可选的自报 skill。

验收：新留出听力首次正常播放后可计入；测验前练过不计；本次提示后仍记录但按支持条件比较；基线与后测技能/难度不符不构成同条件。需生产不公开题面的新材料，再证明正式前后测 happy path 可达，而非只测拒绝路径。

## N6 · P2：页面关系反馈仍没有正确接 API 数据

位置：[V4Path.tsx](../../src/components/V4Path.tsx) 385–394 行；[v3evidence.mjs](../../server/v3evidence.mjs) attemptResult。

API dimensions 返回关系数组；客户端类型和读取仍为 r.dimensions?.relations，导致逐条关系反馈缺失。25 声称网页有“✗反馈”，总 pass 的符号并不能证明逐项解释出现。用户明确希望揭晓后讲清原因，这属于必要体验。

修复：统一响应类型，显示逐关系结果和解释；开放反馈明确低置信。加真实页面用例，核查至少两条逐项反馈，而非只看整体对错。
