# 57 · 首页 Dashboard 与个人学习档案合同
更新：2026-10-03。范围：深化用户已认可的浅色四科课程设计，增加总览；不是恢复旧能力锚点产品。
优先级：最新用户决定 > 本文首页合同 > 56课程与扩建合同 > 55测量/数据合同 > 54教学方法 > 历史文档。

## 产品目标与入口
首页回答：我在哪、各科学了多少、现在该继续什么、错在哪、老师依据什么认识我。
保留课程页邮件式三栏；首页收起课程目录，采用导航＋宽总览。主动作只有继续上次学习；四科各有独立继续入口。
站点地图：[site-map.json](toefl-demo-v2/site-map.json)。可操作样板：[index.html](toefl-demo-v2/index.html)。

## 首页构成
1. 总进度：明确范围和分子/分母，可查看所属课程计划版本。
2. 四科行：科目、当前章、所处活动、完成比例、继续。完成章显示查看本章或下一已发布章，不重复推送旧题。
3. 错题与疑点：不同题首次错误、主动卡点、处理状态；回到自己的原作答和复盘。
4. 个人档案：目标、考试日期、基础、习惯、兴趣、学习偏好、自己感受到的困难。允许修改、删除。
5. 老师观察：原题证据、反复出现的模式、可讨论的原因假设、建议补练、验证结果。每条回溯证据，不只一段通用劝学文案。
6. 空状态：显示如何开始和缺什么信息，不虚构分数、进度、AI诊断。

## 进度口径
原型四科各1章，每章方法/真题/复盘3个活动：单科已完成数/3，总计已完成数/12。因此每科只有0/33/67/100%，不是完整教材的20/30%，不能人为灌数。
正式版分母为用户当前课程计划中已纳入的必修活动总数；选修补课另列，未发布不混进已可学课程百分比。用计划版本固定分母，新增计划时解释比例变化。总进度=sum完成活动/sum计划活动，不能平均四个百分比。
模块与章同口径逐层聚合；视频观看覆盖、课程活动完成、未见题能力验证三条独立记录。跳到视频末尾不算看完；讲义路径也能完成方法活动。
精学练习不冒充模考；熟题重做不增加独立能力证据。不从这四章推算托福分数、全知识覆盖或保证达标。

## 独立继续与数据合同
正式版 ResumePointer：learnerId、part、courseVersion、moduleId、chapterId、activityId、lastPosition、updatedAt。
每科独立保存；首页主继续用最近真实学习事件，而非最近查看档案/错误的页面。返回首页与刷新不丢草稿、录音、首做、播放位置。跨科不串稿。
当前原型以浏览器状态示范，最后访问的科目代替正式学习事件排序；具体局限写入handoff。默认进入首页，不恢复到令人迷失的练习页。
在打开、跳过、提交、完成、复盘、验证等事件中记录具体来源；聚合由事件和版本生成，禁止两套页面各写各的百分比。

## 错题状态机
观察分类：客观首次错误 / 猜对或犹豫 / 主动疑点 / 开放题反馈。
处理状态：待复盘 → 已复盘待重做 → 原题修正待迁移 → 新题验证通过；另有争议、分析失败/待生成。
必须同时展示错误条目数与状态，不把“复盘完成”直接标成薄弱点消失。不同题按canonicalQuestionId去重，尝试次数单列。
原型仅有不同错误和疑点、原章链接，未实现完整状态机；所有条目仍待新题验证，不能称生产就绪。

## 个人信息与AI认识的区别
LearnerProfile可编辑字段：目标/分制/日期、学习时间、基础自述、兴趣和真实应用、困难自述、偏好、课程学习方式。
每字段带来源、记录日期、可更新；自述不是测试成绩。正式版全部字段可改/删，原型只实现目标、日期和当前重点。
Observation：题目与尝试ID、时间、所见行为、证据。
Hypothesis：可能原因、支持/反证、置信说明、本人确认或异议、下一验证任务。少量错题只给线索，不贴稳定能力标签。
AIReview：题目版本、材料引用位置、本人答案/录音/草稿版本、逐项分析、优先改进、追问、对话与语音文本对应、模型/生成状态。
调用失败保存作答，可重试；文字先到即显示，语音失败可继续文字。展示等待、失败、有争议，不伪装已分析。
首页概述需来自这些记录，点入能看到原答案与具体证据。不得把题目预设标签和固定解析冒充个性化AI复盘。

## 四科分析应有区别
听力：声音识别、词义反应、话轮/意图/关系分别检查，引用音频时间段和稿文；转写须本人可纠正。
阅读：定位证据、词义、长句、推断、篇章分开解释，不只判选项。
写作：题目目的、自己的第一稿、反馈后修改版并列；解释最影响读者的一两点，AI改写不作为本人进步。
口语：原音/转写/自我回应分开；重复题的准确保留与采访题的独立表达分开；语音识别错误可申诉。
四科当前所有考试题型仍按55/56保留，样板不能替代全题型覆盖。

## Zcode实施顺序与完成门
H0：用户确认首页操作与四科样板方向；尚未获得整套正式实现批准，当前不是发布指令。
H1：正式数据模型、版本化目录、媒体/来源、浏览器数据迁移到NAS；四科一章先完整迁移，禁止先批量铺空目录。
H2：首页真实聚合、各科继续、档案编辑、错题状态；用真实不同进度数据演示，而非硬编码完成率。
H3：接入真实私人老师；四科各一次真实错答/录音/草稿→文字与语音复盘→本人修改→新题检验。先校准再给分。
H4：老师视频/讲义/原题逐章映射，原题音频/题号/答案人工或可靠审核；确认后按样板扩建，先覆盖每个考试题型代表性单元。
H5：保留池、限时测验、跨题弱项分析、长期计划；能力指标另验，不由章节完成直接升级。
每阶段提交需求映射、真实页面、数据验证、已知缺口；不能以测试总数替代用户能学会一章的验收。
