# 逐字稿校对规范与经验库

版本：v1 · 2026-10-07。适用于 TOEFL Lab 后续新增课程逐字稿；不依赖某个课程或某个模型。

目标：保留真实课堂内容，修正可确认的转写问题，记录不能确认的片段，并提供可追查的出题来源。**读起来流畅、文件生成成功、程序测试通过，都不能代替校对。**

## 1. 这次最重要的经验

| 问题 | 本轮实例 | 新稿的固定检查 |
|---|---|---|
| 英文被误听成另一个合法单词 | 桨手 rowers → rollers；资产语境 shore up → show up | 不只查拼写：看中文解释、句法搭配、本课上下文；不能全库替换同形词 |
| 字母、词缀或词组被拆成碎片 | phrasal verb → phrase over；note-taking → no taking | 连同前后句检查，确认是单词、音标、词根还是老师刻意拆读 |
| 中英文交界误听 | judge 被解释成“偏见”；减重 20 公斤写成“20 公顷” | 同时核对英文、中文释义、词性、单位和例句，不只校英文 |
| 非逐字概述混进课堂正文 | 27 篇稿件开头有原始转写未定位的概述；若干概述混入其他章节词表 | 每个段落要能关联本课原始材料；总结与课堂原文分栏、分文件保存 |
| 后半课丢失，仍被标成完成 | 第 2、6 课在半句话处结束 | 校验全部分块、首尾、段间衔接和尾段覆盖；不只检查文件存在或长度 |
| 错例被当成正确英语修掉 | poor and hunger、people are poverty、object doing | 阅读后续解释；明确标记“错误示范”，保留老师先错后纠正的过程 |
| 老师的联想被当成普遍规则 | 字母形象、谐音、词根联想被用于推导任意单词 | 区分记忆辅助、历史词源与语法规律；缺证据不能升级为事实 |
| 清单比课堂大得多 | 概述生成的跨课词表污染本课清单 | 清单从本节已确认正文提取，每项绑定来源和教学角色 |

本轮实际产物：[复核报告](../docs/transcript-review-2026-10-07/复核报告.md)、[逐条修改台账](../docs/transcript-review-2026-10-07/correction-manifest.json)、[覆盖范围](../docs/transcript-review-2026-10-07/coverage.json)。184 处修改是本轮实例，不是以后遇到相同字符串就必改的字典。

## 2. 原稿、课堂转写和知识纠正分开

保留四个层次，不能相互冒充：

1. **原文件与原始转写**：只读保存。记录文件名、课程/课时 ID、文件签名；识别实际文件格式，不能只看扩展名。本次 `.doc` 实际为 DOCX，真实旧式 `.doc` 不能直接按 ZIP 解析。抽取失败要报错，不能产出空稿充数。
2. **课堂转写派生稿**：保留顺序、口语、必要重复、错误示范。只修有依据的转写问题；确认是老师原话中的语法/事实错误时，保留原话并加编辑注，而不是伪造老师说了正确版本。
3. **复核者注记**：说明正确用法、候选、证据和待核事项，明确“不是老师原话”。普通语法修正也不等于原音认证。
4. **教学整理与可出题清单**：可解释、提炼，但必须标明派生内容；只能使用已经确认的目标，不能把总结、注记或未确认片段作为课堂直接引文。

本地视频/音频用于确认“说了什么”；对应课时讲义/幻灯片用于确认板书或目标拼写；词典等用于确认“知识是否正确”。整本讲义不是本课教学范围证据，OCR 讲义也可能有错。同一段话在另一课出现只是佐证，不是独立听音认证。

当前用户要求**仅本地审核**。后续沿用这个约束；不得因项目存在 DeepSeek 配置、API 密钥或旧脚本而把教材发送出去。若以后明确允许外部辅助，授权须涵盖接收服务和内容范围；模型输出仍只是候选。

## 3. 每次校对的固定流程

### A. 登记与备份

- 列出本批全部课时，先检查编号、文件、讲义和视频映射，防止串课。
- 备份原校对稿及清单，保存源文件和原始转写的 SHA-256；记录预计课时数，不用输出数量推定完成。
- 每课记录实际检查范围：全文文字、英文词项、疑点上下文、听音区间、教学事实。未检查的维度保持未确认。

### B. 先查完整性，再查错词

- 对比原始转写与派生稿的开头、结尾、每个分块边界和正文顺序；定位漏块、重复块、跨课概述和残句。
- 使用文本匹配辅助定位，但保留原始偏移映射。标点/空白归一化后的坐标不能直接用于切原文。
- **“找不到连续 70 字”不证明内容是编造的**；可能是改写或 OCR 差异。疑似非逐字内容先隔离、保留原件、标记待定位，不擅自删除课程知识。
- 字数/时长异常只是报警，不能自动选择最长段当本课。课堂有几个标题也不能决定哪些标题必须删。
- 缺失尾段可从本课原始转写补回，单独登记来源和修订；不能补写一个听起来合理的结尾。

### C. 按上下文确认每个改动

每个疑点至少查看完整句及前后解释，必要时扩大到整个教学段。优先核对：

- 英文目标词、词性、复数、主谓一致、介词、固定搭配。
- 中文释义、专名、数字、单位、否定和条件；一个否定误听会反转答案。
- 学科术语、完整引文、音标与拼读片段；不要把音标噪声提取成生词。
- 老师是在讲正确例句、错误例句、自我纠正、联想，还是顺带提及。

处理结果分为：`confirmed-text-fix`（文字依据足够）、`pending-audio`（需回看）、`editorial-note`（知识辨析）、`teaching-error-example`（保留错例）、`excluded-nonverbatim`（非逐字内容隔离）。文字修订和听音确认分别记录。

不得批量润色整段。拼写替换必须有课程/段落范围、预期命中次数和前后上下文；英文用词边界，避免 unuse → unused 再误改已有的 unused。零命中记为候选未落地；超出预期命中次数停止检查，不算成功。

### D. 重建本课清单

- 遍历完整正文的所有分块，不只处理前 24000 字；保留尾段目标。
- 每项记录标准写法、来源片段和角色：`taught`、`mentioned`、`wrong-example`、`mnemonic`、`pending`。出现过不等于讲解过，讲解过不等于已经可出题。
- 短词根和词缀必须检查边界与实际教学语境；仅做子串匹配会产生假覆盖。
- 只在隔离概述中出现的项目暂移出可用清单，并记录证据；原始转写也有误听，不能据“未匹配”永久判定未讲。
- 清单绑定最终稿签名。稿件改变后，需要重新审查对应清单及题目来源；不自动重生成现有题库或删除旧学习记录。

### E. 验收、发布与报告

- 确认所有课时及所有分块均有处理结果；首尾可定位，遗漏/重复/未定位段落都有记录。
- 复查实际修改次数；检查正确形式没被再次误改，错误示范仍保留。
- 验证每个课稿 API 与发布派生稿一致、清单签名一致，网页能看见待核注记；测试不能代替内容复核。
- 发布前检查原稿未变、生产题库未被顺带覆盖、学习数据未被直接改写。文件写回采用源签名检查、临时文件和原子替换；中途失败不能留下“完成”状态。
- 校对完成与上线完成分别记录；未做听音就不报告“逐字听音校对完成”，只检查英文就不报告“中文全文逐行完成”。

## 4. 交付格式与状态

建议每批保留：`originals/`、`original-inventories/`、`excluded-prefixes/`、缺失段原始备份、`correction-manifest.json`、`coverage.json`、`verification.json` 和中文报告。网页派生稿放 `build/scripts-reviewed/<course>/`，不覆盖素材目录。

下一版通用管线应给每个修改保存以下信息。**这是未来格式合同，当前 20261007 专用脚本未实现全部字段。**

```json
{
  "lessonId": "course-01",
  "sourceSha256": "实际原文件签名",
  "rawSourceSha256": "实际原始转写签名",
  "reviewedSha256": "最终派生稿签名",
  "reviewScope": {
    "sourceAlignment": "partial",
    "englishContextReview": "complete",
    "chineseLineReview": "partial",
    "audioReview": "not-performed",
    "teachingFactReview": "partial"
  },
  "changes": [{
    "kind": "confirmed-text-fix",
    "before": "原片段",
    "after": "修订片段",
    "reason": "具体上下文依据",
    "evidence": [{"kind": "local-transcript", "sourceId": "实际文件标识", "excerpt": "对应片段"}],
    "sourceSpan": {"start": 100, "end": 110, "unit": "unicode-code-point", "basis": "raw-text-lf"},
    "occurrences": 1,
    "audioVerified": false
  }],
  "pendingItems": [{"kind": "pending-audio", "excerpt": "待核原片段", "candidate": null, "reason": "缺词"}],
  "generationReady": false
}
```

示例里的签名、偏移和文字都是占位，不是认证证据。填写真实值；时间戳只在确有音视频定位时填写。无改动的课也需说明检查范围，不能等同于无错。

`generationReady` 与听音/全文审核维度相互独立：是否听音不是唯一出题条件，但被采用的考点必须正确且有完整、可核查的来源。正文和侧车清单签名不一致必须停止生成。

当前 r11 的实现是**逐课整体拦截新生成**，已有缓存可学。以后若允许只从已确认考点生成，必须新增并验证考点级排除能力；不能仅删顶部注记或把全部 generationReady 改 true 来实现。

## 5. 现有工具的使用边界

- [review_transcripts_20261007.py](review_transcripts_20261007.py)：此次 48 课的固定修订表与派生稿构建器，纯本地、检查源签名。**不是面向任何新课程的自动校对器**；不能原样换目录或全局套用替换表。
- [test_reviewed_transcripts_20261007.py](test_reviewed_transcripts_20261007.py)：本批的隔离服务验证，证明响应、签名、缓存和生成拦截行为，不证明语言全对。
- [proofread_scripts.py](proofread_scripts.py)：旧外部 AI 管线，不符合本规范的全部要求，也不适用于当前“仅本地审核”的授权。不要直接运行 `run --force` 覆盖素材旁旧稿。

旧管线已确认的实现风险：

1. 每块都附整本讲义，可能给候选带入跨课知识；这是一种风险解释，不是本轮概述混入原因已被证明。
2. 收到文本就返回，没有检查 `finish_reason`，也没有逐块来源覆盖验收；分块本身不能保证输出不截断。
3. 清单仅来自 `md[:24000]`，长课尾部可能漏项。
4. 文件存在就跳过，未验证源文件签名；有文件不等于与当前素材一致。
5. 正文写入之后再生成清单，后一步失败可能造成稿件/清单不一致；`--force` 可覆盖旧文件，缺少本规范的完整备份和原子交付。

这些风险尚未全部改成通用代码守门；本文件记录的是后续改造合同，不能因文档写完就声称管线已升级。

## 6. 新课交付前勾选

- [ ] 本课文件/视频/讲义关系明确；原稿、清单和源签名已保存。
- [ ] 全部分块、首尾及接缝检查完，漏段/重复/非逐字内容有处理记录。
- [ ] 实际修改有上下文证据、预期命中次数与记录；模糊片段没有猜补成确定内容。
- [ ] 老师原话、知识纠正、联想和错误示范已区分。
- [ ] 全部正文参与清单提取；每个可考点都能追查本课来源。
- [ ] 派生稿/清单签名一致；可用、待核、禁止出题的状态真实。
- [ ] 页面与 API 使用同一版本；原稿、现有题库和学习记录没有误写。
- [ ] 报告写明检查维度、已处理项、待核项、验证边界与是否上线。

课后练的质量要求继续遵守 [quiz-gen-rules.md](quiz-gen-rules.md)。逐字稿来源确认解决“依据是什么”，不能代替题目本身的语言正确、答案唯一和防泄题审核。
