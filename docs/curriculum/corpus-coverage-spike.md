# 语料覆盖度探测与出题管线（spike）

日期：2026-09-28（当日二次修订：修正探针 bug + 加入正确性闸门）。
目的：在写"AI 生成课程"之前，量出**真实语料到底能供多少可用的题**，并验证"检索 → 组合成题"这条路走不走得通。

复跑：
```
python scripts/corpus-probe.py      # 只看覆盖度
python scripts/build-items.py       # 直接产出题目 JSON → out/
```
数据不放在仓库里（许可约束），默认读工作区的 `corpus/`。

## 方法与阈值

- 句子级过滤：2~8 词、无数字 / 引号 / 括号 / 网址、首词之外无大写词（排除专有名词）。
- **最小对立对**：只差目标对比、其余部分完全相同的一对真实句（`I have a dream.` ⇄ `I have many dreams.`）。
- **正确性闸门**：第三人称单数主语后动词必须带 -s（下面说明为什么必须有这道闸门）。

## 覆盖度

| 目标对比 | 命中真实句 | 最小对立对 | 涉及不同词 |
|---|---|---|---|
| 主格/宾格（代词格） | 21,582 | 591 对（过闸门后 **183 对**） | 201 个动词 |
| 单复数（a X / two Xs） | 63,069 | 292 对 | 117 个名词 |
| be 时态（was / am / will be） | 12,429 | 32 组三时态齐全（445 组缺一） | — |

对照：`UD_English-EWT`（新闻/网文，16,622 句）里"代词作主语 + 代词作宾语"且 ≤9 词的句子有 304 句，但**最小对立对 0 对**。

## 结论一：真实句子不缺，但"最小对立对"在自然语料里几乎不存在

EWT 里 304 句目标结构、0 对对立；Tatoeba 有 591 对，是因为它是众包句库、有大量近似重复的变体，不是自然分布。

**所以对立对必须由真实句改造而来**（互换真实句里的代词角色），不能指望现成。这给 AI 一个安全得多的角色：不做"想句子"，只做「改造 + 配干扰项 + 写解析」，每题锚定可核验的真实句。

## 结论二：`attested ≠ correct` —— 语料是脏的，而且脏得很多

这是本轮最重要的发现，也是最反直觉的：

```
12326582  eng  He miss me.        ← 真的躺在 Tatoeba 里
（正确的 "He misses me." 在 200 万句里一句都没有）
```

单靠"第三人称单数后动词要带 -s"这一条最便宜的检查，**591 对里有 408 对被判为变形可疑（69%）**，只剩 183 对进入出题；最终产出 137 道题（其中只有 12 道带中文意思）。

Tatoeba 是志愿者语料，大量贡献者是学习者——**里面混着学习者英语，正是我们要纠正的东西**。所以"直接用语料库"是行不通的：必须加一道正确性闸门，而这道闸门恰恰需要模型（便宜、低风险的任务：判卷与筛选，而不是生成）。

## 结论三：中文意思这一层，Tatoeba 供不上

候选句里只有 **85 句**（约 7%）能找到中文翻译，因此"中文意思 → 英文形式"这类题只能做出 12 道。

两条路：① 让模型为一个**已核验的真实英文句**写中文释义——含义由英文给出，模型只做翻译，这是低风险生成；② 换更大的英中平行语料（OPUS / OpenSubtitles 等，**许可未核**）。推荐①。

## 出题管线的产出形态

`scripts/build-items.py` 不依赖模型，产出 137 道代词格题的 JSON，每题记录**每个选项的来源**：

```json
{ "prompt": "「我想念他。」",
  "options": ["I miss him.", "He miss me.", "Me miss him.", "I miss he."],
  "answer": "I miss him.",
  "optionOrigin": { "I miss him.": "attested", "He miss me.": "attested-mirror",
                    "Me miss him.": "constructed", "I miss he.": "constructed" },
  "errorTags": { "He miss me.": ["role-reversed"], "Me miss him.": ["case-form-subject"],
                 "I miss he.": ["case-form-object"] },
  "sourceId": { "answer": "tatoeba:479775", "mirror": "tatoeba:12326582" },
  "reviewStatus": "draft" }
```

要点：**正确选项永远是真实语料原句**（带 sourceId，可追溯可署名）；干扰项优先用**真实语料的镜像句**（名字就叫 role-reversed，正是中文母语者的典型错误）；其余两条是对真实句框架的**最小违反**，自动带错因标签。所以没有一句是凭空写的。

## 结论四：许可（修正先前说法）

| 池子 | 过滤后 | 许可 | 能否进公开仓库 |
|---|---|---|---|
| Tatoeba 全量 | 1,098,885 句 | CC BY 2.0 FR | **可以，须署名** |
| Tatoeba CC0 子集 | 16,777 句 | CC0 | 可以，但**对立对 0 对**，当不了主力 |
| UD EWT / Pronouns | 16,622 / 285 | CC BY-SA 4.0 | 可以，署名 + 相同方式共享 |

先前把"公开仓库只能放 CC0"讲得太紧：CC BY 2.0 FR **允许再发布只要署名**，所以正确做法是用全量池 + 每题保留 `sourceId` + NOTICE 署名。

`UD_English-Pronouns`（CC BY-SA 4.0，285 句、57 组交替框架）是干净的现成资产，但交替是**跨人称**（hers/his/mine），只适合物主代词这类子技能。

## 尚缺的闸门（下一步）

1. **英文正确性**：目前的 -s 检查只抓一类错误。需要更完整的校验——模型判卷，或与人工标注语料（EWT / GUM / 维基）交叉验证。
2. **考点贴合度**：`It rained five days on end ⇄ three days` 在结构上是"数量词替换"，不是单复数教学点，需要人工/模型再筛一层。
3. **中文释义**：按结论三，用模型为已核验真实句写释义。

## 第二轮：接上模型（DeepSeek）与检索层扩展

接口沿用 molin-wiki 项目的约定（`scripts/llm.py`）：`POST {base}/chat/completions`、`Bearer`、`thinking:disabled`、仅 429/5xx 退避。
**密钥不复制、不入仓库**——运行时从 `molin-wiki/backend/.env` 原地读，环境变量优先。

模型只做三件低风险活（`scripts/enrich-items.py`）：**判英语合法性 / 写中文释义 / 写解析文案**。
解析按张俊杰老师的判定纪律写（落到"含义不同 → 形式不同"，不用术语教学），这段纪律写在 prompt 里当"宪法"。

**延迟实测**：约 **1.8 秒 / 8 题**；137 题全量 32.6 秒。一节课 10 题的模型开销约 2 秒 —— 延迟不是瓶颈。

### 检索层现在覆盖 3 个知识点

| 知识点 | 来源 | 题量 | 模型判定合法 |
|---|---|---|---|
| s2 主格/宾格 | Tatoeba 真实对立对 | 137 | **137 / 137** |
| s4 三单（I like / He likes） | Tatoeba 真实对立对 | 400（抽 40 验） | **40 / 40** |
| s3 物主代词 my/mine | UD_English-Pronouns 交替框架 | 285（抽 40 验） | **16 / 40** |

### 结论五：许可干净 ≠ 可用于教学（修正先前判断）

先前把 `UD_English-Pronouns` 说成"现成的干净资产"。它确实是 CC BY-SA 4.0、确实专为代词交替而造——但它是**语言学测试句集**，不是自然英语：

```
Hers accelerated.      His drove responsively.      Theirs and the dealer's sold quickly.
```

模型判 24/40 为"结构合法但不像人话"。**s3 需要换源，或先过一道自然度过滤。** 对比之下，Tatoeba 派生的 s2/s4 全部通过——说明"真实语料"这条路是对的，只是选哪个语料必须实测。

### 结论六：批量模型校验必须校验"返回 schema"，否则会静默污染

本轮抓到两个**都出在我这边**的静默错位 bug：

1. **缺值被当成判定**：模型有时不按要求的 schema 返回（原样回传输入、用 `zh` 而非 `gloss`、甚至省略 `ok`），而代码把"缺少 `ok`"读成 `False` → 生成出一批**张冠李戴的"不合法"判定**（某句话被贴上另一句话的错误原因）。
2. **批次传参错误**：`ask(items, idx)` 传了全量列表而不是当前批次，导致从第 2 批起，模型拿到的是前 8 条的内容、却写到后面条目上——释义与题目完全错配。

两条教训已固化进代码：**逐条要求显式 `ok`+释义**（缺任一就计"无判定"、不写结论、不当作通过），**"无判定"单独计数并在汇总里打印**。判定可信度不能被静默的 `bool(None)` 偷走。
