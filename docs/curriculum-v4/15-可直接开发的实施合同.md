# 可直接开发的实施合同：数据、决策、接口与验收

2026-09-30｜实施规格 v1.0｜**授权范围仍为规划文档；本文件本身不代表已经实现或允许部署**

阅读顺序：[00 总导航](00-总PRD导航与开发路径.md) → [13 产品 PRD](13-完整产品PRD-需求与验收.md) → [14 首条旅程](14-首条端到端旅程与分流规格.md) → 本文件。这里固定第一批开发的行为合同；开发者可以依此拆工单、建表和实现首条纵向闭环，不必再等一轮抽象访谈。全范围目标的内容生产仍按本文件第 3 节持续进行，不能把“可以开工”误读为“可以宣布完整课程上线”。

## 1. 开发起点与现有系统的真实边界

已只读核对：前端 React 19／TypeScript／Vite；后端 `server/api.mjs` 为无框架 JSON 路由，`server/db.mjs` 使用 `node:sqlite`。旧 `attempts` 按账户和 attempt_id 幂等追加，题库 `items` 有 draft／reviewed／quarantined，客户端 `ProgressV2` 有离线缓存和同步。以上可复用**账户隔离、追加事件、版本、快照、后台日志的工程做法**，不能直接作为新课程的领域模型。旧 `Mode` 仅 recognition／comprehension／construction／oral，旧 `Attempt` 缺首听、字幕、音频来源、录音、开放式评分和目标×技能条件；旧 `reviewed` 是题目审核，不能表示课程质量或学习者掌握。旧 `speak` 使用浏览器语音识别与目标文本相似度，支持自评、跟读／目标句复述；当前代码未发现保存录音或真实互动评价。首版不能把它标为可用的自主口语模块。现有明确锚点：`src/types.ts`、`src/components/Quiz.tsx`、`src/learning/evidence.ts`、`server/db.mjs`、`server/api.mjs`。

**必须处理的语义冲突**：`server/content-ai.mjs` 的现有 REVIEW_SYSTEM 要审核员以旧教材主张为不可质疑标准，并把术语使用视为缺陷。这与 [02 教学边界](02-范围与教学边界.md)和新 PRD 的语言事实核验不兼容。新课程不得调用这一旧审核器作为权威。开发时为新课程建立独立的版本化事实／教学审核合同；旧流水线仅在旧题兼容范围内运行，待迁移评估后再决定替换。不能悄悄把旧 reviewed、旧 speech status 或旧 skill 百分比转换为新能力认证。

## 2. 交付分层与启动边界

|批次|开发者交付|退出条件|可否对用户声称已完成|

|M1 纵向学习闭环|诊断→选择目标→一课→作答证据→不同后继→陌生后测的最小站内流程；先用经审核的少量材料|[14](14-首条端到端旅程与分流规格.md) 三种模拟画像走不同后继；旧账户和记录不受损；未见材料按真实条件评分|只可邀请个人试学，不称全范围|
|M2 按需生成闭环|课程规格生成、质量门、发布与撤回、滚动候选、失败回退与费用日志|每课后可重规划；缓存过期可换；生成失败不循环熟题；坏内容不认证|可声称“首条路径支持按需生成”，不能称自动英语大师|
|M3 听说读写与真实材料|稳定音频播放、录音、反馈复核、真实素材、写作和成长比较|四技能有独立证据；口语人机分歧可查；素材音频／字幕可追溯；新任务迁移可用|本人试用通过后说明实际覆盖范围|
|M4 全图可达与个人验证|216 组逐项原子化／来源对账；各复杂度生成和抽检；延迟与跨场景验证|所有正式目标有可达教学合同，来源细则无无主项；个人陌生任务提升可复核|仅此后可声明“本版全范围按需教学可达”，仍不等于用户都学会|

**并行规则**：M0 的全图账本可持续扩充，M1 不必等待 72 个单元全部成品化；但每一批必须交代本批目标与全图的关系、未覆盖清单和下一批责任人。架构开发可与内容核验并行，未经核验的内容只能作为开发 fixture，不能发布给学习者。以上批次是依赖顺序，不是时间承诺。

## 3. 原子目标与来源账本的统一格式

[coverage-ledger.csv](coverage-ledger.csv) 已从现有地图建立 72 单元／216 目标组的逐项工作账本，五个首条旅程相关组标为 `first_path`；其中五组已在 [17](17-首条路径原子目标与事实核验.md) 各拆三条首批目标，并在 [18](18-首条路径诊断与课程材料包.md) 有材料草稿；五个父组仍缺完整细则对账、音频、人审与试学，其余 211 组的原子化状态仍标 `pending`。该 CSV 是工作状态，不是“全英语已核验”的证据。开发每完成一项，要填原子 ID、实际来源定位及各项状态，不能只把 `pending` 改成 `done` 而没有可查产物。

每个 K 组至少生成一条原子目标；通常一个 K 会分解为多个可独立测量的目标，**数量由语言事实决定，不预设 216 就是终点**。稳定 ID 形如 `O-K115-01`，不能因措辞变化复用不同含义。每条必填：父 K／U，能力层（结构／声音／词汇语块／交际），可观察行为，形式—意义—使用边界，必要前置（目标 ID，不是只写单元号），可区分的常见错误，至少一个有意义的输入任务和一个输出或互动任务，适用技能与不适用说明，复杂度维度，教学策略候选，来源定位与查阅状态，版本，负责人，验证状态。

来源定位必须指向实际读过的页节／词条／课稿行号；只有目录级来源时状态为 `scope_only`，不得写 `fact_verified`。原课解释保留“教学启发”属性，语言事实另有核验来源；外部 CEFR／GSE／English Profile 用作能力出口与对照，遵守原始使用边界，不复制受限库作产品资产。覆盖账本每个参考细则有明确去向：`teach`、`diagnostic_skip`、`advanced_reference`、`out_of_scope_with_reason`、`unmapped`；`unmapped` 可以存在于工作版，正式“全范围”发布时必须为零。U72 不是遗漏收容箱。每次新增目标要检查前置图无环、同义重复、四技能出口和旧证据版本影响。

**首条旅程的种子目标（设计占位，尚非事实核验完成）**：`O-K115-01` 在文字长句中追踪外层主张与嵌套修饰；`O-K007-01` 在正常语流中识别功能词弱读后仍抓主张；`O-K184-01` 在短讲授中辨认主张、证据和限制；`O-K190-01` 不看原文用自己的英语复述主张及理由；`O-K194-01` 针对观点回答一次未知追问或提出澄清。它们只是实现首条纵向闭环的目标 ID 建议；正式教学前逐条写边界、对比例、来源及可接受答案。不要从名称推断用户已掌握。

## 4. 新领域对象与持久化合同

在旧表旁新增版本化对象，不原地改写旧题和旧 attempts。建议表名可按仓库约定调整，但**实体关系和不变量不可省**：

|实体|主键／核心字段|不变量|
|---|---|---|
|`objective_versions`|`objective_id + version`，父 K/U、行为、来源、状态、前置版本|发布过的版本不可静默覆盖；旧证据绑定原版本|
|`media_assets`|`media_id + version`，类型、来源／授权、时间段、校对稿、存储位置、可播放状态|字幕与原音分版；撤销使用权即禁止新分发|
|`lesson_versions`|`lesson_id + version`，目标、策略、材料版本、任务家族、内容包、质量结果、发布状态|每次改答案／目标语义递增版本；已作答版本可回看|
|`learner_attempts_v3`|`account_id + attempt_id`，lesson／activity／objective 版本、条件、原始回答引用、评分|只追加且幂等；第一次尝试和后续提示尝试不互相覆盖|
|`evidence_events`|`account_id + evidence_id`，目标×技能×复杂度×条件、评估结果、依据、争议状态|从尝试和审核派生；撤回坏题用反向事件而非删除历史|
|`learner_states`|`account_id + objective_id + skill + complexity`，当前证据状态、版本、更新时间|可从 evidence_events 重建；自评免修不等于认证|
|`plan_decisions`|`account_id + decision_id`，画像快照、候选、选择／排除理由、策略、版本|每次推荐可回放；不能只存最终课 ID|
|`generation_jobs`|`job_id`，输入合同、模型／提示版本、重试、费用、产物、校验、失败原因|异步可重试但不重复发布；失败不阻塞已审核课|
|`oral_reviews`|`review_id`，录音／转写版本、维度、证据位置、评估者、分歧|ASR 低置信和用户修正有独立记录|

录音大文件不塞进 `attempts.answer` 或 JSON 同步包，数据库只存受权限保护的引用、时长、校验和状态。默认个人试用采用**明确操作后上传、可回放、可删除**，不在未告知情况下发送到第三方；具体保留期和供应商接入在语音实现前形成可见设置。开发阶段用合成或授权样本，不用真实个人录音做自动测试。所有新写入限定 account_id，读取和删除都验证账户范围；现有账户切换不是公开多用户认证，公开推广前须另建身份与访问控制。

## 5. 状态机与证据升级

**内容状态**：`draft → checking → review_needed / ready → published → withdrawn`。`checking` 未过结构／来源／答案／素材／重复任一关键门则到 `review_needed`，不得自动发布。`ready` 表示验证通过但尚未进入学习队列；`published` 可被分发；`withdrawn` 停止新分发且触发受影响证据复核。修订从新版本的 `draft` 开始，旧版与作答保留。自动审与人工抽检各记来源及结论，不把同一模型两轮自夸当独立审查。

**学习证据状态**按目标×技能×复杂度：`unmeasured → tentative → trained → independent → transferred → retained`，并行标志 `waived_by_user`、`disputed`、`needs_repair`。独立证据必须是首见、无答案泄露、无提示且内容可认证的任务；`trained` 可以包含提示后成功。`transferred` 需要不同任务家族与场景；`retained` 需要间隔后的新任务。旧 04 的“3 家族、2 场景、7 天”是待校准初值，可作为首版暂定认证门槛，不得伪称已验证测量学阈值。用户斩掉把同层同质练习从推荐队列移除，但状态可为 `waived_by_user`，不能变成 `retained`。坏题／坏转写只追加 `disputed` 并暂停负向更新；复核结束再更正或撤回。不同技能不相互升级：读对关系从句不能认证听力，跟读不能认证自由口语。

**计划状态**：`candidate → ready → served → completed / skipped / invalidated`。每节后即重算；缓存内容可因画像变化转 `invalidated`，保留费用和弃用原因。推荐请求只读取 `published` 且适配目标的课程；正在生成时可从经审核候选中取下一节或说明等待，不调用旧题凑数。

## 6. 决策规则 v1：先可解释，再优化

入口初始化仅形成候选差距：文字关系、无字幕听辨、词汇／语块、脱稿表达、互动。每次选择下一行动按以下固定优先序过滤，而非先给模型一个模糊总分：①剔除材料无效、目标版本失效、超出授权的内容；②若当前失败可能由题目／录音／转写错误引起，先复核材料，不降低用户状态；③若根因有两种以上合理解释，给最短的区分任务；④否则优先选与课堂／生活目标相关、前置已具备、证据薄弱且能打开后继的原子目标；⑤避免最近任务家族和已斩掉同层内容；⑥按当前能力挑难度，只升一个主要维度；⑦选策略：已会挑战先行，新概念短讲先行，声音卡听辨，输出卡检索／互动；⑧生成或取课；⑨记录选择和被排除候选。排序同分时固定以“目标重要性→前置解除数→较少重复→目标 ID”决定，保证同一快照可回放。

**诊断停止**：当至少有一条可解释、可供给的近期学习路线，且继续测下一题预计不会改变头两节目标时，停止入口测评并公开未测区域。目标时长 5–10 分钟是体验假设，不能因计时到点就伪称已定位；若音频权限不可用，可先走文字路线但听力保持未测。连续错误两次触发区分根因或改变支撑，不自动降整个等级。**策略调整**只在新任务表现与原策略相比有可靠改善／恶化证据时进行，记录原因和回退版本；单个偶然表现不全局改地图。

## 7. 课程包契约与生成质量门

一个课程包至少有：版本化目标与前置，学习者适配条件，预计难度维度，一段可读的“为何现在学”，精华讲解或挑战入口，输入素材（真实或原创；音频任务必须可播放且有校对稿），2–4 个不同功能的任务（不要求固定题数），分层提示，揭晓后解析和可接受变体，输出活动，独立保留任务引用，失败后分支和下一目标候选。任务必须显式标 `practice / diagnostic / transfer / holdout` 角色；同一底层材料改人名仍属同家族。保留题的答案、字幕和摘要不得提前泄露给学习者或训练生成器。

生成分两步：先由规划器产出目标／策略／素材规格，再由内容生成器产出课程包；验证器独立检查。质量门依次为：schema 完整、目标／前置存在、来源和授权可用、语言事实和适用边界可靠、答案／评分口径自洽、音频字幕与时间点一致、语义家族不重复、难度实际增加、保留题隔离、输出反馈不贬低合理变体。任何关键门失败记录原因并返修；重试有上限，仍失败则撤出候选，不得默认 `published`。新语言事实或复杂自由回答要人工例外复核和抽检；用户不被要求逐题当审核员。模型服务失败时从已审核课程中选适配内容；都没有则明确“当前可用内容不足”和下一步处理状态。

第一版预取默认只生产**接下来 2 节完整可学课 + 最多 4 个目标候选位置**，并在每课后重估；这是可开发的初始参数，试产时依据等待时间、费用、弃用率调节，而非产品永远固定为 2+4 或十节。指标须记录生成到可用时延、单节费用、验证拒收率、撤回率、候选弃用率和用户等待时间。不能仅追求出题吞吐量。

## 8. 首批 API 合同（建议作为新 `/api/v1` 域）

旧 `/api/accounts/:id/sync` 和题库 API 保持原契约；新领域独立，避免把课程包塞进旧 Question 或整份 ProgressV2。以下路径是第一版接口名，若实现时因路由约束调整，必须保持语义、幂等和返回形状，并同步本文件。

|方法与路径|请求核心|返回核心／错误|
|---|---|---|
|`GET /api/v1/map`|可选 `version`、`status`|目标索引、版本、覆盖缺口；未验证目标明示状态|
|`POST /api/v1/accounts/:id/diagnostics`|`requestId`、可选起点偏好|`diagnosticId`、第一任务、已测／未测；重复 requestId 返回同一结果|
|`POST /api/v1/accounts/:id/attempts`|`attemptId`、activityVersion、回答／录音引用、支持条件、曝光条件|保存的事件、评分状态（可同步／待评）、更新后的证据引用；重复 attemptId 幂等|
|`GET /api/v1/accounts/:id/plan`|无副作用，可带 `afterDecisionId`|当前推荐课、选择理由、候选／等待状态和证据摘要|
|`POST /api/v1/accounts/:id/plan/recompute`|`requestId`、触发事件 ID|新 decisionId、被替换候选和原因；服务端串行化同账户决策|
|`GET /api/v1/accounts/:id/lessons/:lessonId`|明确版本|仅返回该账户可访问且 published 的学习包；holdout 答案不返回|
|`POST /api/v1/accounts/:id/oral`|录音上传意图、媒体类型／大小|一次性上传位置或拒绝原因；随后以 attemptId 绑定，默认不隐式传第三方|
|`GET /api/v1/accounts/:id/evidence`|目标／技能过滤|可追溯状态、分条件证据、争议与用户免修|
|`POST /api/v1/accounts/:id/waivers`|目标、技能、复杂度、用户原因|`waived_by_user` 事件；不返回已认证|
|`POST /api/v1/accounts/:id/content-reports`|lessonVersion、问题位置、描述|报告 ID、课程是否暂停认证；用户无需知道工程管线|

所有写接口校验账户、请求版本和大小；新尝试先落库再异步评分，返回 `pending_review` 时前端不显示确定判错。生成任务走后台 job，不在用户的同步答题请求里调用长模型。服务端必须能通过事件重放重建画像；每次状态变更记录触发的 attempt／review／withdrawal。录音请求受文件大小、类型、时长和账号配额约束，具体数值在真实设备试产后冻结，不能先放开无限上传。公开多人版上线前另做身份认证与访问控制；本地单人试用不得误以账户 ID 已是安全认证。

## 9. 界面状态与失败回退

首页显示个人主线“当前目标→为什么→下一步”、四技能独立证据和未测区域；不可把 XP、题量、旧箱数作为主进度。诊断页展示首次任务与可暂停；没有麦克风时允许文字继续，同时说明口语／听力证据未测。课程页先原声／任务，提示按层展开；揭晓解释原因，保留原回答；录音页可播放自己的回答、看转写并纠错；成长页对照同条件的旧作与新作，标注“提示后”和“陌生独立”。内容正在准备时给可用的已审核后继或清楚的等待状态，不回退旧题伪装课程。用户报告题目问题后暂停该题认证，但保留学习历史。

音频播放失败、录音权限被拒、ASR 超时、模型超时、素材撤权、生成内容拒收、评分冲突、客户端离线、两个标签页同时完成课程都要有明确状态；不把技术故障归咎于学习者。旧客户端离线练习继续可用；新口语与按需生成在线依赖不可用时不伪造成功。新状态写入采用版本比较或事务防止并发丢失；恢复断点与旧 `active_sessions` 的交互需要集成测试。

## 10. 验收测试矩阵与不可妥协的失败条件

|测试组|给开发者的 fixture／步骤|通过证据|
|---|---|---|
|T1 目标覆盖|抽查 U01、U03、U39、U62、U64、U68、U71，以及一个低频高级目标|每个目标有原子行为、来源状态、前置、技能出口；未核验不显示“已覆盖”|
|T2 三种画像|14 中“基础已会”“文字会声音卡”“理解会口述卡”三套事件|三种 next-plan 的目标与策略明显不同，理由含证据；同一输入重放结果稳定|
|T3 争议与坏材料|字幕故意错、ASR 故意错、答案两个可接受变体|课程／尝试标争议，用户不降级，holdout 不被污染|
|T4 斩掉|基础目标自评已会；之后做复杂任务失败|基础同质练习从日常队列消失；复杂失败只开局部短修复|
|T5 生成质量|空字段、无来源、不可播、答案不一致、语义重复、模型截断|全部不得发布；有明确返修／失败日志；旧 published 版本不丢|
|T6 窗口与服务故障|在学第 1 课时改变能力证据；模拟模型长时间失败|未学缓存替换，费用与弃用记录可查；有适配后继或诚实不足状态|
|T7 口语|跟读成功、自由复述失败；噪声导致转写低置信|跟读与自主表达证据分离；后者待确认且能查看／修正转写|
|T8 多账户／历史|两个账户同目标不同表现；旧 300 多题历史；同一请求重发|互不串数据；旧题只作线索；attemptId／requestId 幂等；快照可恢复|
|T9 学习效果|两周内等条件陌生材料前后测，加数周后另一场景任务|保留原始听说读写作品、支持条件与独立评分；熟题提速不算达标|

**直接判失败**：发布内容教错关系或把歧义判用户错；一题／一次 ASR 给出“已掌握”；已斩掉基础仍成批重复；缓存学完没有后继且默默重刷；诊断三种根因走同一课；旧数据被覆盖或跨账户；生成器声称全图覆盖却留下无主参考细则。通过单元测试但未通过这些旅程，不能说产品目标完成。

## 11. 开发交接的工作包顺序

1. **W0 对齐与保护**：建新域而非直接重写旧题系统；旧数据快照、只读映射、API 兼容测试；明确新旧双轨展示与回退。验收 T8。
2. **W1 地图生产工具和首批目标**：按第 3 节建立账本、原子目标版本与前置验证，完成首条旅程目标事实审查，并给所有 K 组状态。验收 T1；后续持续扩到全图。
3. **W2 诊断与证据**：做第 4–6 节事件、状态、决策；用三套 fixture 完成入口与根因分流。验收 T2、T3、T4。
4. **W3 可学习的纵向课程**：制作并核验 14 的 D1–D3、L1–L4 材料；先允许人工审过的静态课走完，不强依赖自动生成。验收 T3、T7、T9 的基线可采集。
5. **W4 自动生成供给**：接目标规格→候选素材→课程包→质量门→版本发布→窗口重规划；记录时延／费用／弃用；旧 AI 审核 prompt 不用于新课程。验收 T5、T6。
6. **W5 口语与真实材料**：接站内录音、播放、转写复核、开放输出评价，验证 YouTube Digest 复用边界；默认录音由用户明确触发。验收 T7 和真实素材 T3。
7. **W6 本人试学与全范围扩展**：先两周陌生任务比较，调整策略和阈值，再逐组完成来源对账与多复杂度抽检。验收 T9、T1 全范围版本；未完成时保持范围声明诚实。

MCP 与语音供应商的具体接法、版本和准入试验以 [16 选型合同](16-MCP与语音能力选型-接入决策.md) 为准。W2 的 Tutor MCP 是隔离影子对照，不能成为唯一学习状态；W5 先打通浏览器录音，发音 MCP 和 Azure Speech SDK 均须试验后才可进入正式路径。

每个工作包结束交付：改动文件、对应 R ID 和 T 用例、运行验证、真实内容覆盖清单、未解决问题、下一工作包可用输入。不要把 W3 首条路线做成长期 demo，也不要因为 W1 全图工作大就只做基础题。代码评审与教学事实审查分开进行。需要付费语音或第三方托管、个人录音留存方案时，先给用户具体方案和成本；其余工程细节由开发团队依据本合同决策并记录。
## 12. 请求与返回样例（字段语义固定）

以下 JSON 是新域的**合同示例**，不是已存在的接口，也不是正式教学素材。服务端持有正确答案、校对稿与保留题，不在作答前返回给客户端。

`POST /api/v1/accounts/:id/attempts` 请求示例：

```json
{
  "attemptId": "at_01J_example",
  "sessionId": "diag_01J_example",
  "activityId": "act_audio_claim_01",
  "activityVersion": 1,
  "objectiveIds": ["O-K184-01"],
  "response": { "kind": "text", "text": "The speaker compares two uses but I missed the conclusion." },
  "conditions": {
    "firstExposure": true,
    "inputMode": "audio_only",
    "transcriptShown": false,
    "playCount": 1,
    "hintLevel": 0,
    "lookupUsed": false,
    "responseMode": "typed_summary",
    "taskFamilyId": "claim_contrast_audio_A"
  }
}
```

服务端检验 `objectiveIds`、条件和任务家族与发布版本一致，不能信任客户端自报来提升证据。返回 `attemptId`、`saved: true`、`evaluationStatus: pending | evaluated | disputed`、`evidenceEventIds` 和 `nextAction: wait | continue | review_transcript`。重复相同 `attemptId` 返回第一次结果；同 ID 不同正文返回冲突错误，不覆盖原始作答。

`GET /api/v1/accounts/:id/plan` 的关键返回示例：

```json
{
  "decisionId": "pd_01J_example",
  "mapVersion": "map-v1",
  "learnerEvidenceVersion": 18,
  "primaryGoal": "O-K184-01",
  "strategyId": "listen_claim_before_transcript-v1",
  "reason": "文字能辨认转折，但两段新音频的首次理解均漏掉结论。",
  "hypotheses": ["sound_segmentation", "realtime_relation_tracking"],
  "uncertainAreas": ["spontaneous_interaction", "writing"],
  "lesson": { "id": "lesson_01J_example", "version": 2, "status": "published" },
  "fallback": { "kind": "reviewed_alternative", "lessonId": "lesson_backup_01" },
  "notChosen": [
    { "objectiveId": "O-K115-01", "reason": "文字层已有独立证据，不应整条路线回退。" }
  ]
}
```

课包中的每个 activity 至少携带 `activityId`、`version`、`role`、`taskFamilyId`、`objectiveIds`、`inputAssetIds`、`responseKind`、`hintStages`、`evaluationContractId`；课包另含 `whyNow`、`strategyId`、`difficultyDimensions`、`prerequisiteEvidence`、`nextCandidates` 和 `sourceRefs`。用于学习者作答的返回包不得含 `holdout` 的答案、完整校对稿或隐藏评分要点。允许对用户展示的解释在作答结束后通过受控接口揭晓。

建议统一错误码：`ACCOUNT_NOT_FOUND`、`VERSION_CONFLICT`、`ACTIVITY_NOT_PUBLISHED`、`MEDIA_UNAVAILABLE`、`EVALUATION_PENDING`、`CONTENT_DISPUTED`、`GENERATION_UNAVAILABLE`、`REQUEST_ID_REUSED_WITH_DIFFERENT_BODY`。错误必须能转成可理解的学习者状态，不能统一报“答错”或“网络异常”。

## 13. 旧数据与新能力的迁移判定

|旧记录|新系统用途|禁止的升级|
|---|---|---|
|旧 reviewed 题的确定性首次作答|候选诊断线索；目标 ID 与版本可信时可提示跳过低层练习|不得直接认证听力、自由口语或跨场景保持|
|旧 speak 的 transcriptMatch 或自评|知道用户曾尝试跟读／目标句复述，可用于选择口语入口|不得当录音已保存、发音可靠或自主回应达成|
|旧 XP、题量、box、ladder 层级|展示历史活动与迁移说明，保留用户投入|不得转换为新目标完成比例|
|旧被 kill／fix／有争议的题|保留历史和回溯，排除新认证池|不得因为旧题曾做对就放行相关目标|
|旧账户题库中正确且有来源的内容|按新目标／家族／来源重审后可作练习素材|不得仅因为旧 reviewStatus=reviewed 就发布为新课程|

迁移先在数据库副本演练，记录旧记录数、新增事件数、无法映射数和抽样核对结果；正式迁移要可回滚且不删除旧表。新旧页面在过渡期明确标记来源，避免用户看到两个互相矛盾的“掌握率”。
