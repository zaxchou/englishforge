## 必修问题

### F1 · P1：生成器看不到素材正文，最新发布课仍要求回答原文不存在的信息

位置：server/v3registry.mjs:52（materialsForPrompt），server/v3gen.mjs:307（生成提示），server/v3gen.mjs:164（materialsBound）。提示只提供 materialId/kind/sourceRef/note；正文未提供。门只验证 ID 可绑定，不验证实际可答性。

只读真实库的具体反例：gen_job_mup9n39c_n3dk_2，课程 gen-o-k115-03-vmup9n8fc，绑定 mat_g4_discourse_markers。题面要求“现在先做什么/先不做什么、以后还打算做什么”，提示要求找现在/以后、推迟。实际材料是博物馆地图：访客走向拥挤展室，团队对访客偏好的假设不完整；没有推迟事项或未来计划。用户认真读懂原文也无法正确回答题目。

修复：给生成器确切材料版本、具体片段正文；问题、参考答案、解释、提示都绑定该片段，并保存支撑句/范围。不存在支撑信息即拒收或进入内容复核，不靠 materialId 合法或模型自报 allPassed 发布。阅读素材含多个段落时必须明确选择段落，不将整包同时显示而题目指向不清。

### F2 · P1：错误的语法提示与目标串挂已经进入真实生成记录

真实样本 gen_job_mup7v5h4_n4qx_1：“加逗号的那部分，如果去掉后意思变了，它多半在缩小范围”；把逗号附加说明当作限定判断的提示不可靠，且此题属于 O-K115-03 对照与限制，却混入限定/非限定对照。gen_job_mup80ov3_7tae_0 又把两类关系句合并成同一个“被测试那颗”的限制答案，没有真正测出限定与补充的区别。最新 gen_job_mup9n39c_n3dk_1 提示仍固定“前面是主张，后面是限制”，容易把 but/although 的位置当作机械规则，而不是按具体语义判断。

这不是追加关键词可以修好的问题。先建立目标—材料—问题—答案的人工可审样例与反例，核查原理边界。错误已发布样本应撤出后继候选，保留旧作答并标记内容争议；不得静默修改历史题义。新活动必须版本化。

### F3 · P1：内容签名不覆盖素材正文，重启也无法发现正文变动

位置：server/v3registry.mjs:63–70，server/v3gen.mjs:515–520。签名只含 mapVersion 与来源 claim/limit，完全没有 materialsVersion、正文、目标定义、评分合同。除了 sigCache 的进程缓存问题，即使重启服务，修改博物馆正文而保持地图版本/来源命题也得到相同签名。旧生成课仍按新正文显示，答案却按旧内容保留，任务定义哈希也没有把外部正文纳入。

修复：使用完整的不可变内容依赖清单/哈希，覆盖目标版本、材料片段正文与版本、评估合同、生成合同；发行任务冻结材料版本，历史回放取旧版本。在途生成及未开始课程检测依赖变化，明确作废；已开始课使用冻结内容完成或明确撤回，不偷偷换正文。

### F4 · P2：所谓“定义快照冻结”仅冻结模态与复杂度，不能证明完整历史可复现

位置：server/v3evidence.mjs:411–414、588–599。activity_snapshot 只存 simulatesAudio/audioRef/complexityBand/skillByObjective；旧无快照行仍回退当前定义。未保存题面、材料正文版本、evaluationContract/evaluatorVersion。注意：本轮未证明 recomputeStates 会按新 slots 重新判旧答案，它目前主要重放事件；因此不能把 33 自报的风险直接写成“已复现重新判题”。但 27 要求的旧定义可追溯仍未完整满足。

补完整版本档案与重放合同，并增加“原定义→内容/答案换版→读取历史、重算、复核”测试。旧无版本来源标记不可完整复现，不能伪造快照。

### F5 · P2：素材池把自行编写/自行校订标成 audited，且三个阅读池对所有目标开放

位置：server/data/v3-materials.json，server/v3registry.mjs:32–35。前三项 objectiveIds=[]，任何目标都可绑定；一个非空合法 ID 不代表适合该目标，更不代表已由合格评阅者核验。33 已承认零真人核验，与代码注释“来源/许可/文本已核”不一致。

把机器检查、自校订、专业复核分字段；开发样本明确身份。加材料可支持目标/技能/复杂度与片段范围，不能用无限制通用素材填满全知识地图。
