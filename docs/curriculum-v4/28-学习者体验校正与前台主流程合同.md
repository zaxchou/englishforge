# 学习者体验校正与前台主流程合同

2026-10-01｜页面源码基线 9e1ca89｜承接本人实际反馈：能力路径页看不懂

## 1. 产品判断

后台的能力图、诊断、推荐和证据是个体课程所需基础，但当前前台没有形成用户要的循序渐进学习体验。问题同时涉及信息架构、教学主流程和可用内容，不能只做视觉美化，也不能要求用户读懂后台模型再开始学。

本轮依据当前 App/V4Path 页面源码与已确认需求判断，没有查看本人此次实际浏览器画面。因此页面显示的账户数据/部署版本可能不同；后续必须在本人使用版本走查。本报告不声称做过现场可用性测试。

[27 后续开发合同](27-后续开发路线与交付合同.md)是实施主线，[26](26-封闭判题与测量链路复审.md)是已复现缺陷。本文件具体约束 27 的 D1 学习者主流程，并提升其优先级：可信数据合同修复与主流程设计同步推进，不能修完所有后台再考虑用户体验。不能把开发诊断控制台当正式成品展示。

## 2. 当前为何看不懂

[App.tsx](../../src/App.tsx)默认进入旧 home，返回学习空间也回旧路径，新域是一个附加入口；用户面对两个关于学习和进度的体系。

[V4Path.tsx](../../src/components/V4Path.tsx)默认推荐页，五个标签是当前推荐、入口诊断、我的证据、能力地图、审核与试听。首次进入先看到双轨迁移说明；推荐标题直接是 O-K…，策略/根因/未测领域用内部名称；证据以目标×技能×复杂度行展示；地图突出拆解与核验统计；管理员审核入口与学习入口并列。这些有助于开发复核，但不能回答学习者最先关心的下一步。

复杂度带还被命名成“认识/造句/辨析/口说/迁移/解释”，会让阅读 band4 被误解成口说能力。难度与技能不是一条标签序列，应显示实际任务负担，例如“简单指代/嵌套指代”，并独立显示听或读。

课程页即使能提交作答，也不等于已有教学节奏、连续挑战、清楚讲解和可信成长。内容仍有开发样本/待审核，近期后继有限。这一部分是功能与内容欠缺，不是把 ID 换中文就解决。

## 3. 正式学习入口只回答四件事

1. 我目前在练什么能力，和听课/交流有什么关系。
2. 现在点击什么就可以开始或继续。
3. 这次训练依次怎么进行，需要多久；时间只是估计。
4. 结束后我比刚开始多会了什么，接下来为什么学那个。

后台保留原始 ID/条件/来源，前台使用经过校订的行为名称。个人路线只显示当前与近期可解释后继，不把整个 72 单元图铺成强制解锁关卡。远期目标可以看，但不能把待生产内容画成已可用课程。

## 4. 用户主流程与页面合同

### A. 今日学习：默认入口

有未完成训练时主按钮“继续学习”；新用户主按钮“用几分钟找起点”。不是先让人挑诊断/推荐/证据三个模块。建议展示：

- 近期目标：听懂一段项目讨论，并说明观点的限制。
- 今天这一步：分清一句话中的主张、原因和补充信息。
- 安排理由：上次文字能读懂，但声音里漏了转折后的限定。（仅在有真实证据时显示。）
- 主按钮：开始训练 / 继续上一段。
- 辅助入口：我的成长、学习路线、历史练习。

没有诊断证据时直说需要找起点，不能预写个人弱点。先保留历史记录，再把旧刷题降为明确的“历史练习”入口；新入口只在 D0/D1 可用条件满足后设为默认，不能将不能学习的页面强制顶上。

### B. 找起点：任务流，非术语报告

开头说明“先试几项任务，已经会的会跳过；不确定的会在学习中继续确认”。题目逐步变难，已会快速前进，争议/技术失败有恢复入口。

结束只显示已确认现象、未测范围、推荐开始点。例如“这一段你能读懂，但首听遗漏了原因；先练一次声音分段”。没有足够证据则“先从这项挑战确认”，不输出假确定等级。根因代码、原始诊断表放可选详情。

### C. 一节训练：一次只有明确当前动作

课程阶段可按任务调整，但学习者应知道自己正在：理解原理→听/读输入→抓关系→说/写出来→新情境挑战。基础已会可跳过短讲。每次页面突出一个主要动作，材料和所需工具就近呈现，不把整课全部题目、所有标志和审核信息一次堆出。

提示逐层出现；失败后能再试，揭晓后讲清为什么以及原理边界。说/写任务用于表达，不能全部改成选择题；选择题帮助定位。看稿成功与独立成功区分，但以自然话解释，不要求用户学会 evidence schema。

### D. 课后反馈：把结果和下一步连起来

展示具体作品或关系上的变化，例如“最初把实验室当设备，现在能在另一句中分清对象与事件”。只有真实前后记录支持才用此表达；没有比较则显示本次表现。

反馈分三类：本次完成了什么、哪里仍需练、下一步。练习参与不能写已掌握；待复核输出可显示完成与建议，同时明确暂不确认能力。主按钮继续下一步或结束今日，不能完成后重新落回一张内部推荐表。

### E. 我的成长：人能理解的能力变化

默认按实际行为与作品展示：读懂嵌套关系、首听抓限定、脱稿解释方案、回应追问。听说读写分别说明条件和未测范围；展示近期录音/写作与相似难度新任务的变化，不显示未经校准的总掌握百分比。

ID、证据事件和复杂度槽表可折叠为高级详情。不要让学生逐格分析 trained/independent/retained 才知道进步。

### F. 学习路线：当前→近期→长期方向

显示个人主线及必要支线，说明“为什么绕到这里”和“完成后回哪里”。已会可跳过，后续暴露缺口只局部补；内容等待提供可用备用训练或清楚等待说明。全图未审状态留在运营账本，用户需要看的是真实可学范围和长期方向。

## 5. 学习端与运营端分开

“审核与试听”、目标版本/来源审签、生成 job、核验数量属于运营/开发端，不能与学生主要导航并列。学习端可以显示必要来源和音频类型、反馈试听问题；专业审核职责不能交给本人。

开发状态要诚实，但集中成清楚且有操作意义的提示，例如“这段内容还不能正式学习，先练这段可用材料”；不把 W3、fixture、claim_checked 等实现术语当用户提示。没有合格内容时不可把换皮开发题当主线填空。

## 6. Zcode 下一批实施顺序

1. 在改大量页面之前，先交一个覆盖 A→B→C→D 的可点击原型/受控页面，用同一个具体任务贯穿，补上 E/F 的示意数据。所有虚构演示状态标为演示。原型可以使用已修正材料，不能借此绕过生产证据门。
2. 同步执行 26/D0 的阻断修复；在原型中定义统一 learner view model：行为名称、当前任务、可用状态、下一动作、可读理由、成长摘要，后台完整审计数据保持独立。
3. 用户端落实恢复学习、单任务节奏、提示/重试、课后继续与自然语言反馈；运营页分离，旧记录仍可访问，不删历史。
4. 接入 D1 三节完整训练与一段已听校真实材料，证明讲解、听读、表达、挑战和后继是同一条线。
5. 先由开发者在真实页面走查，再请本人做短程可用性体验；据反馈修改，之后才扩批和进入 D2 个体滚动生成深化。

原型评审和内容生产可与可靠性修复交叉。不要再交一张“诊断/推荐/证据”后台表作为产品 UI 验收，也不要以美化卡片代替学习节奏。

## 7. 本人体验验收

进入页面后，无须读 PRD或工程说明，能说出现在要做什么；首次用户有唯一明显的开始入口，回访者有继续入口。本人能知道题目为何安排、答错怎么办、是否需要看稿、完成后新增什么或尚未知什么，以及下次做什么。无需在诊断、推荐、证据标签间手动协调流程。

走查包含：新用户找起点、有基础快速跳过、读会听不懂分支、失败提示后重试、录音/短写作、完成续课、中途退出恢复、素材不可用/待评分降级。至少一条连续体验使用真实内容与真实账户条件，不能全靠预设演示答案。

最终是否值得本人持续投入，需本人短程使用和之后的学习变化验证。当前只能够判断后台路线可保留，但现有前台与内容交付尚不是用户要的完整产品；看不懂属于应由产品解决的问题。
