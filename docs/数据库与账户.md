# 账户与进度数据库

进度不再只躺在浏览器里。现在有两份：**浏览器 localStorage**（当前工作的那一份，离线也能练）和
**SQLite 数据库**（长期、可查询、可回溯的那一份）。两者自动同步，数据库不可用时应用静默退回纯本地模式。

```bash

```

启动日志会打印一行 `[englishforge] 进度库已就绪 <路径>`，那就是库的位置。

## 怎么查询

```bash
python scripts/db.py                        # 总览：账户、XP、连续天数、作答事件数、首发正确率、到期题数
python scripts/db.py objectives             # 每个知识点：题数 / 作答 / 首发正确率 / 跨几天 / 变式家族数
python scripts/db.py errors                 # 错因分布（来自选项级 optionTags）
python scripts/db.py days                   # 每日练习与 XP
python scripts/db.py questions -n 40        # 作答最多的题（找"反复出现"的题用这个）
python scripts/db.py sessions               # 每次练习的记录
python scripts/db.py snapshots              # 存档快照列表
python scripts/db.py attempts -n 50         # 最近的作答事件流水
python scripts/db.py sql "SELECT question_id, COUNT(*) FROM attempts WHERE outcome='incorrect' GROUP BY 1 ORDER BY 2 DESC LIMIT 10"
```

标准库 sqlite3 只读打开，零依赖；也可以用任何 SQLite 客户端直接连文件。

## 表结构

| 表 | 内容 |
|---|---|
| `accounts` | 账户（id / 名称 / 创建时间 / 最近活动）。当前默认只有一个 |
| `meta` | 每账户一行：XP、连续天数、最近训练日、连击、**revision**（服务端单调递增的状态版本） |
| `attempts` | **作答事件，只追加**。按 `(account_id, attempt_id)` 主键幂等；`error_tags` 存选项级错因 |
| `question_states` | 题级复习状态：stage / due_at / correct / total / 口语自评 / 是否来自 v1 迁移 |
| `skill_progress` | 技能级历史练习记录（仅供推荐与统计，不再映射成掌握百分比） |
| `practice_sessions` | 练习记录（对应界面"最近练习"） |
| `daily_xp` | 每日 XP |
| `active_sessions` | 未完成会话的断点（冻结队列 + runtime JSON），刷新可续 |
| `content_reviews` | 内容审核标记（通过/要改/毙掉 + 备注）——也是用户的工作成果 |
| **`items`** | **账户题库**（内容层）：语料派生的题与将来即时生成的题。`payload` 存整道题（前端契约），列上存 skill/source/review_status 便于筛选统计 |
| **`item_batches`** | 每次导入/生成留一条批次（生成方式、题数、备注），用于"两批题对照" |
| `snapshots` | 整份存档快照，保留最近 30 份 |
| 视图 `v_objective_stats` | 按知识点聚合：作答、首发、首发正确率、跨天数、变式家族数 |
| 视图 `v_daily` | 按训练日聚合 |
| 视图 `v_item_stats` | 题库按思维点 × 来源 × 信任级别聚合 |

**题库不是进度**：`items` 与 `content_reviews` 不参与"清空进度"（`resetAccount` 只清 attempts / question_states /
skill_progress / practice_sessions / daily_xp / active_sessions）。题是你的资产，审核结论决定"这题算不算能力证据"。

## 同步协议

```
POST /api/accounts/:id/sync      { baseRevision, state, attempts[], reviews, reason }
POST /api/accounts/:id/replace   整份替换（导入存档 / 首次把浏览器进度搬进库，先留快照）
POST /api/accounts/:id/reset     清空进度（先留快照）
GET  /api/accounts/:id/progress  取整份存档 + 审核标记
GET  /api/accounts/:id/stats     聚合统计（界面面板用的就是它）
GET  /api/accounts/:id/attempts  按题目 / 知识点筛选事件
GET  /api/accounts/:id/items       账户题库（?skill=&status=&source=），附带按思维点的统计
POST /api/accounts/:id/items       导入题目（幂等：同一 itemId 只更新）+ 批次
PATCH/DELETE /api/accounts/:id/items/:itemId   逐题定版 / 删题
GET  /api/accounts/:id/batches     批次列表
GET|POST /api/accounts/:id/snapshots, POST /api/snapshots/:id/restore
POST /api/bootstrap              库里没账户就建一个（"默认先做第一个账户"）
GET  /api/health                 库位置、账户数、大小
```

**合并规则**（这是"不丢"的关键）：

- **作答事件只增不减**：`INSERT OR IGNORE`，按 `attemptId` 取并集。重发不会重复计，漏发会被补上。
- **状态整份覆盖**：单用户单设备，最后写入者为准；`revision` 只作诊断，不做拒绝（少一类"我的进度没存上"的故障）。
- **覆盖 / 清空 / 导入前必留快照**，快照记的是**操作前**的状态 —— 即"你可能想要回来的那一份"。

客户端只推"上次之后新产生的"事件（游标 = 上次推送的最后一条 `attemptId`）；游标失效（超出 5000 条上限）
时回补最近 500 条，靠幂等性保证不重复。

## 启动时的接管决策

唯一"猜错就会丢进度"的地方，所以它是纯函数并有测试（`src/store/db.test.ts`）：

| 本地 | 数据库 | 决策 |
|---|---|---|
| 有 | 空 | **整份搬进库**（老用户第一次跑；服务端先留快照） |
| 空 | 有 | **接管库里的**（换了浏览器 / 清了缓存） |
| 有 | 有 | 本地为准 + **事件取并集**（离线练的那一轮不会被覆盖掉） |
| 空 | 空 | 全新开始 |

## 界面上的位置

- **顶栏徽标**：`已存入数据库 / 数据库未连接`，点一下进「回顾」页。只在练习、课程、回顾等内页出现。
- **首页底部一行**：`已存入数据库 · 账户「默认账户」共 N 条作答记录`。
- **回顾 → 账户与进度数据库**：账户改名 / 新建 / 切换、立即写入、按数据库重载、库内统计
  （作答事件、首发正确率、练过的题、到期、审核标记、快照）、各知识点原始统计、错因分布、快照恢复。

首页刻意不放这些东西：那里只回答"下一步做什么"。

## 题库怎么进来

```bash
python scripts/build-items.py      # 语料 → 题（out/items-*.json）
python scripts/enrich-items.py     # 模型补释义 / 逐项纠正 / 判据
python scripts/push-items.py       # 导进账户（幂等；已富化的才导）
python scripts/db.py items         # 看题库分布    ·  db.py batches 看批次
```

`push-items.py` 的取舍：`itemId = <skill>:<语料id>`（可追溯、可反复替换）；跳过 `sourceRef` 已在仓库题目里的
（避免同一句语料进两次）；**只导模型富化过的**（没富化的缺逐项纠正，宁缺勿错）。

## 已知边界

- 数据库是**单机本地的**，不是云。它的价值是"不会因为清浏览器缓存而丢""可查询""可回溯"，
  不是多设备漫游（多设备需要把库放到服务器上，接口已经按这个方向设计好了）。
- 客户端存档上限 5000 条事件（原有约束）；数据库保留**全量**，超过上限的旧事件仍可查询。
- 状态是最后写入者为准：同一账户同时在两个浏览器里练，后写的那边会覆盖状态（事件不会丢，
  会被并集补回来）。真要多端并发，得把状态改成按事件重算。
- `vite-plugin-db.mjs` 在测试环境（`VITEST`）下不安装中间件 —— 测试绝不能碰真实用户数据。
