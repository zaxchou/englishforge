## 先说用户从哪里进、学什么、到哪里去

**入口**：侧栏「学习路径」→ 今日学习卡。用户当前位置（O-K115-03，旧关系课已完成）现在直接显示**开始训练**，进入新链第 1 节《主张、对照和限制：分清再复述》：

1. **精华短讲**（g3c_principle_pick）：30 秒讲清主张／对照／让步／限制的区别——限制只能靠句中实际的收窄内容判断，明说"but/although 后面不一定是限制，没有划范围就如实说信息不足"；两空封闭题确认原理（选项里埋了"逗号后就是限制"这类机械规则当错误项）。
2. **明确输入**（g3c_rehearsal_locate）：下发排练记录段原文，三空定位（保留什么／推迟什么／限制条件）+ 理由栏；正文、题目、参考答案、判据同源（活动定义里存支撑原句，可审计）。
3. **挑战与恢复**（g3c_paraphrase_recover）：先用自己的话复述；漏了词表锚点→不通过→**三层提示逐层给可用词族**（第三层直接给出 keep／推迟／"先在展厅试过再定"的说法方向）→再试通过。照抄原句被 mustNot 拒（"要用你自己的话"）。正确等义复述不再无路可走。
4. **实际输出**（g3c_write_limit）：2–3 句小写作（为什么推迟、限制是什么、为什么不是"语音不行"）；如实标注**写作练习：反馈不计入能力记录**；mustNot 挡照抄、挡"永久取消"式错误结论。
5. **新情境迁移**（g3c_film_transfer）：换材料（放映与配音段）+ 换任务形状（判断每句话在做什么：对照／限制／未来计划）。
6. **连续推进**：完成后重算——主目标仍在 O-K115-03 时推荐第 2 节《新情境检验：博物馆地图的结论》（g4c_claim_limit_slots + g4c_recap_write，新素材新任务）；若 O-K115-03 已达独立（按既定"2 家族独立答对→independent"策略），推荐给出具体下一步与理由，链尾空态显示一键生成入口与免修出路，不停在"内容准备中"。生成失败/审核未过时，今日卡给"重新生成一次"与"先学备用课"（备用=策划链本身，预置、不依赖生成成熟）。

两节课都接真实前台入口（今日卡/推荐卡→LessonRunner），保留刷新恢复（resume/重新读取当前任务）、历史作答留档、开发样本说明。没有音频的任务如实标读/写，未冒充听说训练。

## 工程约束落实情况

### F3：内容签名覆盖完整内容依赖；失效不靠重启
- `contentSignature()` v2：哈希**地图种子全文 + 来源账本全文 + 素材池全文**（正文/版本/适配/状态）+ 三份内容合同版本束（`CONTENT_CONTRACTS`：评估/生成/语义审核，回归断言与 `GEN_CONTRACT_V1`、evaluatorVersion 一致）。改任何一个段子的一个字 → 签名变。
- 三处进程缓存（来源账本/素材池/签名）全部按**文件 mtime+size 戳**失效：改数据文件立即生效，"以重启服务当失效规则"的缺口关闭。
- 发行即冻结：生成活动注册时把所引段原文存 `materialSnapshot` 落库；已开始课的下发正文**只取冻结快照**（素材后改不改写已发行内容），无快照旧活动回退实时读取。listen 素材永不发正文的硬规则在统一入口 `materialForLearnerFrozen` 执行（快照不得成为绕过口——测试覆盖了"换绑 listen 素材的快照"反例）。
- 适配表扩目标（mat_g4 + O-K115-03）带 R3 要求的用途说明（阅读补练、能支持的具体问题、不认证听力），素材版本随之递增。

### F4：完整版本档案 + 隔离库四场景
- 作答快照从"模态+带"扩为**完整定义档案**：题面原文、评分合同全文、目标/技能/家族/角色/版本、素材绑定与冻结正文。`recomputeStates` 的回放继续按快照判（坏快照回退当前定义，覆盖面见 32 号报告，不伪造）。
- 四场景隔离库复现（`v3freeze.test.mjs`，全程临时库+测试缝替换签名输入，不动真实文件）：①正文变化→在途任务失效；②正文变化→未分发个体课不适用、恢复后重新适用；③已开始课用冻结正文完成、素材改版不改写下发内容；④合同换版→历史作答评估原文不动、重放状态不被新合同改写。

### S1：语义审核拿到它声称要兜底的全部依据
- 审核输入现在包含：目标行为与边界、精华讲解（teachingNote）、**每题全部提示**、评分合同全文（relations/polarity/mustNot）、参考答案、支撑句、所引段正文、判题机制说明与正确/错误样例定义。
- 机器强制（不靠模型自觉）：**必审字段缺失 → 即使注入的 judge 自报 supported 也强制 pending**；输出缺任一题任一维度 → pending；**listen 素材无审核转写 → 可答性不可测 → pending**（不再让空输入背书听力题）。unsupported 是更严结论，保留原样不降级。
- 默认模型审核改为逐题四维度输出（可答性/语言事实与解释/目标对齐/评分一致性），输出不可解析 → pending。
- 审核对象哈希 `reviewHash` 落档（S2 发布前核对"审核背书的对象=要发布的对象"）。
- 测试：输入字段真实到达审核器的捕获断言、缺 hints 强制 pending、缺维度强制 pending、listen 强制 pending（38 号三类注入要求各有着落）。

### S2：审核返回后的发布前最终核对
- `runSemanticReview` 返回后、写库前重读：任务状态（仍 running）+ 学习证据快照（审核期间无新作答）+ 内容签名（审核期间素材/合同/来源未变）。任一不过 → **不发布**；最终状态变更带 `WHERE status='running'` 条件——外部 supersede 不被"迟到的好评"覆盖，成本与原因留档（`INVALIDATED_DURING_REVIEW` / `SUPERSEDED_DURING_REVIEW` 两种原因分开记）。
- 测试：暂停审核器→期间追加作答→释放 supported→不发布且 superseded；暂停期间外部改状态→原状态与原原因保持、返回 SUPERSEDED_DURING_REVIEW。

### S3：审核/预览状态三处一致 + 恢复路径
- 服务端同一份事实源：`publishLesson` 时把 `contentPreview/humanSignPending` 写进课包质量门；`serveLesson` 响应带 `contentReview{preview,humanSignPending,semanticVerdict,pending}`，devSampleNotice 区分"内容试验预览（机器门+模型辅助审核已过、专业核验未做）"与普通开发样本；`listJobs` 暴露解析后的 `published/pending/semanticVerdict`——前端不再把"succeeded 但没课"当成功。
- 前端三处：①生成结果页（今日卡 done 态）明示"内容试验预览"；②推荐卡（PlanPanel）chip"内容试验预览 · 模型辅助检查已过 · 专业核验未做"；③课头与课程响应同口径，刷新/缓存恢复后重取课包仍带。审核未过（unsupported/pending）与 superseded 分别给明确说明 + "重新生成一次" + "先学备用课"恢复按钮；等待理由文案同步更新。

## 走查实测抓出并修掉的真实缺陷（不是编造的反例）

1. **中文槽位选项判题塌缩**（严重）：槽位代号归一会剥掉非 ASCII 字符——纯中文选项全部归一成空串，任何中文选择都与空 accept 相等判"正确"（静默放水）。已修：归一保留 CJK（`[^a-z0-9\u4e00-\u9fff]`），ASCII 代号行为不变。这正是"只有课程内容错误阻断交付"级别的问题，由链路测试第一次用中文选项实测才暴露。
2. 理由栏合同缺 `label` 导致输入框不渲染；理由关系原为 required，留空会把选择全对的题压成不通过——与"理由栏可选、理由未测=中性参与"的设计冲突。已修：理由=加分项，不门控 pass；目标结果仍按 partial 中性参与（不升级不计败）。
3. 冻结快照优先级与 listen 规则的冲突（人工换绑素材的反例）在测试中暴露，统一入口修复。
