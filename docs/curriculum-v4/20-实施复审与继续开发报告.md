# 实施复审与继续开发报告

2026-09-30｜复审基线 7205e19｜面向 Zcode 的下一轮开发合同

## 1. 结论与效力

现有实现已经搭起诊断、课程、生成任务、口语和试学记录的框架，但尚不能认定 W0–W6 的退出门槛全部通过，也不建议直接开始正式个人效果试验。关键问题是系统会把未实际测到的能力记成进步，完成课程后仍推荐原课，以及测试记录不能可靠证明学习前后变化。这些问题会重现用户最不满意的体验：做题很多，却无法确认自己为什么进步、下一步去哪里。

[19 实施合规报告](19-实施合规报告-W0-W6.md)如实披露真实音频为零、未真人试学、模型余额不足等限制，这些披露应保留。它关于测试通过、机制已经实现的陈述，需要结合本报告的失败路径重新判定。以 [13 产品 PRD](13-完整产品PRD-需求与验收.md)、[15 实施合同](15-可直接开发的实施合同.md)为需求依据；本报告补充复审缺陷和下一轮验收；[21 修订包](21-目标证据对齐与材料修订包.md)修正首批目标与材料的对应关系。不要改写 19 以抹去历史状态，应另写修复后的证据报告。

本轮只审代码和补文档，没有修改应用代码、真实学习数据库或部署。

## 2. 实际验证及其边界

在映射盘 Z: 下运行全量 Vitest，14 个文件、211 个测试全部通过；新域测试单独运行 27/27；TypeScript 项目编译通过。首次 UNC 路径运行遇到工具路径解析问题，改用 Z: 后解决，不计为产品缺陷。

另用独立临时数据库复现下文的失败路径，不调用外部模型，不污染真实数据。现有测试全绿与这些失败同时成立，说明回归用例尚未覆盖关键产品语义。代码位置以基线提交为准，修复后行号可能变化。

## 3. 必须先修的问题

### F1 · P1：开发成绩、文字模拟音频和已显示提示进入正式能力状态

位置：[证据计算](../../server/v3evidence.mjs)约 55、124、199–277 行；[生成与注册](../../server/v3gen.mjs)约 47–66、196 行；[学习界面](../../src/components/V4Path.tsx)约 280、321、361 行。

复现：提交 diag_d2_listen_sim 的必需关键词，声明未看字幕、无提示，返回 pass=true，并为四个目标生成 listening/trained 状态。该活动实际只有文字，标有 simulatesAudio。fixture 置信度也未被正式状态计算排除。生成活动注册时丢失 transcriptShownByDefault 和 oralEvidenceDeferred，文字口语活动同样能得到 speaking/trained。界面自动展示 firstHint，却仍可提交 hintLevel=0。证据聚合还把所有复杂度合并成 objective×skill，无法区别简单关系与嵌套关系。

修复：开发 fixture 与正式学习证据分域；服务器核实输入模态、实际材料、提示暴露及活动版本。文字模拟声音只可测阅读；缺录音不得测口语；保留生成活动的证据限制字段。按目标×技能×复杂度及支持条件保存证据，不能靠客户端自报获得独立掌握。

验收：无音频的文字模拟不改变听力；无录音不改变口语；fixture 不改变正式状态；默认提示计入支持；复杂度不同的表现不能互相覆盖。历史受影响证据要可追溯重算，不能静默删除原始记录。

### F2 · P1：完成课程后不推进，入口诊断长期压过新证据

位置：[完成课程](../../server/v3lessons.mjs)约 178–197 行；[推荐](../../server/v3plan.mjs)约 25、148、207、222 行；[界面刷新](../../src/components/V4Path.tsx)约 70–78、334、345 行。

复现：完成首条路径 L1 后，GET /plan 返回同一 decisionId、状态 completed；主动重算后虽然 ID 改变，仍给 O-K115-01 和同一 les-relations-v1。界面却显示推荐已按新证据重算。完成校验仅依据账户曾提交过这些活动，没有绑定本次课程会话与版本。入口诊断中的 route、primaryGoal 和 hypothesis 可持续强制原路线。

修复：课程完成产生唯一事件并触发推荐更新；推荐读取返回当前可执行决策，或明确 content_pending。初始诊断是可被后续证据修正的假设，不能永久锁定路线。完成只认本次会话对应活动和版本；界面只在真实重算成功后宣称更新。

验收：连续完成 3–5 节课，独立成功、提示后成功、关系误判分别产生合理后继；重复完成不重复更新；不存在可用后继时明确告知，不能默默把已完成原课再当新课。

### F3 · P1：候选窗口包含被排除目标，课程选择不匹配目标

位置：[推荐输出](../../server/v3plan.mjs)约 251 行；[课程查找](../../server/v3lessons.mjs)约 259–270 行；[滚动窗口](../../server/v3gen.mjs)约 266–287 行。

源码显示 ensureWindow 直接使用 decision.candidates，其中包含 notChosen、免修、前置未满足等排除项。lessonForStrategy 只按策略找课，未匹配个人选定目标、技能、复杂度和条件，之后却缓存到所选目标名下；缓存版本写死为 1，已有静态课版本为 2。生成课统一 global scope，未建立个体内容与公共内容的复用边界。

修复：输出独立的 eligibleRankedCandidates 与 exclusions；生成只消费前者。课程检索核对目标、技能、复杂度、策略、版本、适用条件和账户范围。公共受控材料可共享，包含个人表现的定制内容需限定范围。任务族去重不能只比较可随意改名的标签。

验收：免修和缺前置目标不进入生成队列；同策略不同目标不能错配；版本准确；个人内容不跨账户复用；重命名旧题不能伪装陌生迁移。

### F4 · P1：关键词判定不能作为开放理解与逐目标掌握证明

位置：[判题](../../server/v3evidence.mjs)约 55–73 行；[活动登记](../../server/data/v3-activities.json)；[材料修订包](21-目标证据对齐与材料修订包.md)。

复现：无关系的词袋 gesture delay crowded still want 能通过；正确回答“保留手势，延后语音，因为展厅多人，仍计划探索，并未完全放弃语音”因包含否定语境中的“完全放弃”反而失败。同一总 pass 赋给全部目标，D1 没有询问 which 的指代范围，却能给 O-K115-02 记成功。

修复：题目、问题、答案证据和原子目标逐项对齐；每目标返回 met/partial/unmet/unmeasured/disputed。资源不足时可以用受控关系题加人工复核开放回答，但不能把词袋检测包装为理解认证。无法可靠判断应 disputed，技术失败也不能算学习失败。

验收：纳入正确改述、否定、主体互换、因果倒置、只答一半和关键词拼接的反例；未测目标没有成绩。21 的 CT01–CT04 是可审阅的新增文字草稿，需完成目标审签后入库。

### F5 · P1：口语签署可以认证不存在的录音，单一维度覆盖内容失败

位置：[口语存储与签署](../../server/v3oral.mjs)约 65、149–198 行；[录音界面](../../src/components/V4Path.tsx)约 494–501 行。

复现：给 les_l1_sensor_read 的阅读作答签署口语评估，不上传录音，内容维度 0、清晰度 3，其余 0，接口仍返回成功，并产生 speaking/trained。签署只要求非空 evaluator 和一个数值维度；overall 使用 some(dim>=2)，静态活动技能查找未覆盖，默认成 speaking。非空文件直接 playable=1，也未证明它是可播放音频。

修复：先验证录音可读、可解码、时长有效，并绑定账户、attempt、活动版本和具体录音 take；只为实际测到的维度写证据。内容和任务完成度须有明确门槛，不能被声音清晰覆盖。静态与生成活动统一查技能。保留历史机器评估与人工评估，新增签署不能覆盖原始评估。可信评阅人也须通过这些检查，不能用“鉴权以后再做”解释当前缺陷。

验收：无录音、错账户、错活动、坏文件不能签署口语；内容错误但发音好不能过任务关；阅读活动不被升级为口语。支持重新录一遍，使用新 take/attempt ID；当前固定 oral+activityId、durationMs=0 的路径必须修正。

### F6 · P1：诊断能跳步骤，重试会重复推进

位置：[诊断状态](../../server/v3diag.mjs)约 50–59 行；[提交入口](../../server/v3api.mjs)。

复现：新诊断会话直接提交 D3 即 completed，步骤只有 D3；重复提交相同 attemptId 的 D1，存储作答虽幂等，诊断步骤却变成 D1、D1。未判定或争议结果还可能按失败推进。

修复：服务端只接受当前会话实际发出的活动与版本，校验账户、分支前置、attemptId；作答与诊断推进事务化。相同请求返回既有结果，不产生第二次推进；disputed 保留待处理，不强行分流。

验收：乱序拒绝、正确分支可达、重试不重复、跨会话不能提交、争议不降级；步骤记录必须携带真实 attemptId。

### F7 · P1：T9 预注册和前后测记录允许事后补录、覆盖基线

位置：[试学机制](../../server/v3trial.mjs)约 41、62–79 行。

复现：先产生作答，再注册试学计划，仍可作为基线 counted=true；同一 baseline 再提交支持条件不同的记录，INSERT OR REPLACE 覆盖既有基线。材料核对主要依赖任务族，未严格绑定材料版本、预注册时间和阶段顺序。

修复：正式计入作答必须晚于预注册并匹配已发材料及版本；基线追加保存，纠错采用新版本和理由。按真实提示、首次暴露、音频/字幕条件判定可比性；不同条件可展示，但不能自动标成同条件提升。后测和延迟测有阶段约束。

验收：事后预注册不能计入既往作答；不能覆盖基线；错误材料版本、提前后测、已曝光留出题不计入正式比较。18-L4 已公开，仅是设计样例；需生产用户未见过的新留出版本。这里要求修测量机制，并未把尚未真人试学本身当作代码错误。

### F8 · P1：生成输入缺个人学习证据，来源标签不等于事实核验

位置：[生成输入和质量门](../../server/v3gen.mjs)约 71–81、125、155–161 行。

当前任务输入主要是目标与生成合同，缺个人最新错误、根因、支持条件、复杂度和学习证据版本。提示提供通用来源代码，sourcesUsable 只查全局白名单；任意合法代码不能证明该材料的具体规则。语法术语黑名单还禁止“从句”等正确概念，会妨碍高级内容的精确解释。旧的主语类比不能强制替代完整语言知识。

修复：生成合同加入 learnerEvidenceVersion、目标版本、根因和策略、难度条件、来源的具体命题与边界、逐目标评价合同、最近任务族及必要错误样本。内容生成与评分检查分开；新语言命题需核验，可靠模板变体可按风险实行独立自动检查。允许先清楚解释、再给有帮助的准确术语。个人输入与缓存范围同时修。统一校验生成开关，字符串 0 不能启用，直接接口也不能绕过禁用状态。

验收：同目标的“读懂听不懂”和“听懂说不出”产生不同合约与后继；缺来源支持、证据过期、相同任务换名、关闭开关均不能发布/调用生成。先通过注入假供应商验证，不需要付费模型；之后少量真实生成审样，不能一次补齐 216 组。

|C5 本人试学|依赖 C0–C4 的相关退出条件；先短程可用性试学，再两周及延迟测|记录真实理解、复述、互动、写作与条件，不用题量证明成效；不满足可比性则明确保留不确定性|

C2 的人审可以由真实具备能力的评阅者完成，不能由开发 agent 自填名字伪装完成。正常学习者不应承担管理员式签署工作。若尚无可靠开放评分，先明确人工复核/等待状态，保留可正常完成的受控训练路径。

模型 402 不阻塞规则修复、假供应商验收、人工校订文本或浏览器音频播放。它确实阻塞未缓存内容的真实生成，必须显示准确降级状态；不要以充值或扩展 MCP 数量替代上述闭环修复。16 的候选接入仍须实测，当前不存在一个装上即可拥有“英语大师”诊断能力的已验证 MCP。

## 5. 首批内容与全范围工作的剩余责任

[17](17-首条路径原子目标与事实核验.md)的 15 条原子目标和来源只支持局部事实，不代表 216 组已核验。[21](21-目标证据对齐与材料修订包.md)补的是 which 对比、嵌套关系、否定与开放回应的文字修订，尚无新音频、实际人审或效果校准。真实可用课程仍须把文字、声音、评价、条件和连续后继一起交付。

保持全图覆盖账本：当前 5 组部分草案、211 组待拆解。每完成一条路径，同时更新其前置、边界、四技能出口和下一层目标；不要暂停全图责任，也不要为展示完整而批量生成无人会学的课。
